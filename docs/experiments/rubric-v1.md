# L1-1 루브릭 v1 — 프롬프트 pairwise 심판 채점표

> 짝 문서: [`docs/experiments/experiment-plan-v1.md`](experiment-plan-v1.md) §2 L1-1.
> 이 문서가 5축 채점의 **단일 진실 소스**다. L1-1 표 안의 한 줄 요약("if절 단서 구체성" 등)은
> 여기를 참조만 하고 재정의하지 않는다 — 정의가 두 곳으로 갈라지면 한쪽만 고쳐지는 사고가
> 난다(이 레포에서 이미 여러 번 겪은 패턴, 예: `eval/README.md`가 전역 금지어를
> `safety/banned_words`에서만 읽도록 못박은 것과 같은 이유).
>
> **왜 이 문서가 따로 있는가**: L1-1 은 `docs/experiments/experiment-plan-v1.md` §11 이
> "루브릭 확정"을 W1 게이트 항목으로 못박아 뒀다 — 5축이 표 한 줄 요약으로만 있으면
> 채점자(사람이든 LLM 심판이든)마다 "구체성"·"unpacking" 을 다르게 해석해 재현 불가능한
> 숫자가 나온다. 축별 1~5점 앵커(구체적으로 무엇이 1점이고 무엇이 5점인지)와 심판
> 프롬프트를 코드로 옮기기 전에 텍스트로 먼저 고정한다.

## 0. 이 루브릭이 채점하는 것

L1-1 은 같은 실패 상황(태그·전략·컨텍스트)에 대해 프롬프트 버전(v1/v2/v3)이 다르게 만든
if-then 카드 텍스트를 **쌍대비교(pairwise)** 로 채점한다. 심판(LLM 또는 사람)은 매번
**두 후보(A/B)** 를 동시에 받아 5축 각각을 1~5점으로 매기고, 최종 승자를 정한다.

**심판이 보는 것**: 카드 텍스트를 이어붙인 한 문장이 아니라 **구조화된 필드**다 —
`if_clause` / `then_clause` / `rationale` (v1/v2), v3 부터는 `obstacle` / `coping_clause`
가 추가로 있을 수 있다(현재 미구현 — S5, `docs/research/recovery-evidence-base.md` §3).
축 ②/③(then절 unpacking, coping절 독립성)은 필드가 나뉘어 있어야 서로 다른 절인지
판별 가능하다 — 이어붙인 문장 하나만 주면 두 절의 경계가 사라져 심판이 구조를 못 본다.

**심판이 같이 받는 컨텍스트** (`routes/recovery.py` 가 실제 프롬프트에 넣는 변수와 동일):
`failure_type`(태그), `strategy_label`/`strategy_group`(룰이 고른 전략), `base_template`
(카탈로그 원문), `context_summary`(실행 카드 제목 + 결과). 심판은 **이 컨텍스트 밖의
사실을 후보가 지어냈는지**(축 ⑤)를 판별해야 하므로 반드시 같이 받는다.

## 1. 5축 정의 + 1~5점 앵커

각 축은 **후보 하나에 대해** 독립적으로 채점한다(A 따로, B 따로) — 비교는 점수를 다 매긴
**다음에** 한다(§2). 채점 도중 "A가 B보다 나으니까"로 점수를 매기면 앵커가 무의미해지고
축 간 상쇄가 생긴다.

### ① if절 단서 구체성

실행 의도(implementation intention) 형식의 핵심은 "특정 상황(if) → 행동(then)"이다. if절이
막연하면 단서가 실제로 발생했을 때 사용자가 그걸 알아채지 못한다.

| 점수 | 기준 | 예시 |
|---|---|---|
| 1 | if절이 아예 없거나, 시간·장소·직전 행동 중 아무것도 지정 안 함 | "언젠가 시간 날 때" |
| 2 | 막연한 시간대만 있음(장소·행동 단서 없음) | "오늘 중에" |
| 3 | 시간대 + 막연한 장소는 있으나 구체적 트리거는 아님 | "저녁에 집에서" |
| 4 | 장소 또는 직전 행동 중 하나가 구체적 트리거로 작동 | "책상에 앉으면" |
| 5 | 장소·직전 행동이 결합돼 사용자가 즉시 알아챌 수 있는 트리거 | "저녁 먹고 책상에 앉으면", "아침 지하철을 타면" |

**감점 요인(공통, 모든 점수에서 -1, 최저 1점)**: "오늘"/"내일" 같은 날짜어 포함 — v2 프롬프트
자체가 금지한 것이다(카드가 나중에 재노출되면 거짓이 된다, `if_then_proposal.v2.md`). 날짜어가
있으면 트리거가 아무리 구체적이어도 최대 3점을 넘지 못한다.

### ② then절 unpacking (범위 축소가 아니라 분해인가)

근거 대장 B7(Kruger & Evans 2004, unpacking)의 핵심 주장: "전체를 N분만" 은 **시간을
자르는 것**이지 **하위 단계로 나누는 것**이 아니다. 후자만 실제 착수 장벽을 낮춘다.

| 점수 | 기준 | 예시 |
|---|---|---|
| 1 | then절이 원본 카드 제목을 그대로 반복(개인화 없음) | "GROUP BY 실습하기" |
| 2 | 시간만 잘랐을 뿐 과제 범위는 그대로("전체를 N분만") | "GROUP BY 실습 10분만 해봐요" |
| 3 | 과제를 줄였지만 어느 하위 단계인지 안 밝힘 | "GROUP BY 실습 조금만 해봐요" |
| 4 | 하위 단계를 지목했으나 그 단계가 여전히 뭉뚱그려짐 | "GROUP BY 실습 앞부분만 봐요" |
| 5 | 카드 제목 + 식별 가능한 하위 단계 + 소요시간(5~15분)이 모두 있음 | "GROUP BY 실습에서 예제 1절만 떼어 15분만 봐요" |

**AGENTS.md §8-11 참고**: v2 프롬프트 자체의 예시(`if_then_proposal.v2.md:50`)가 실제로
이 축에서 2~3점대(시간 상자 프레이밍)에 걸린다 — 이 루브릭이 지금 v2 를 채점하면 낮은
점수가 나오는 게 **버그가 아니라 이 축이 존재하는 이유**다.

### ③ coping절 독립성 (then 반복이 아닌가)

근거 대장 B2(장애물 대응 계획): action plan(if-then) 만으로는 부족하고, **장애물이
생겼을 때 뭘 할지**(coping)가 별도로 있어야 실행 의도 효과가 커진다. v1/v2 는 이 필드가
아예 없다 — 있다면 `rationale`에 섞여 있을 수 있으므로, rationale 텍스트도 이 축의
채점 대상이다.

| 점수 | 기준 |
|---|---|
| 1 | coping 관련 언급이 전혀 없음(v1/v2 의 기본 상태) |
| 2 | rationale 이 있지만 감정적 위로일 뿐 "장애물이 생기면"에 대한 대응이 아님 |
| 3 | rationale 이 장애물을 암시하나("좀 컸던 것 같아요") 대응 행동을 안 줌 |
| 4 | 장애물 + 대응이 있으나 then절과 사실상 같은 행동의 재진술 |
| 5 | then절과 **다른** 구체적 대응("그마저 어려우면 ~라도")이 명시적으로 있음 |

**동어반복 경고**: then절이 이미 최소 단위(5분)까지 축소돼 있으면 "그게 안 되면?"에 답할
자리가 논리적으로 없다 — 5점을 받으려면 **더 작은 대안**이거나 **다른 종류의 행동**(예:
"그마저 버거우면 오늘은 그냥 눈으로만 훑어봐요")이어야 한다. then절을 토씨만 바꿔 반복하면
아무리 그럴듯해도 4점을 넘지 못한다.

### ④ 톤 (주어가 사람이 아닌가) — **동률 tiebreak 축**

근거 대장 §8(하지 말아야 할 것)이 가장 강하게 미는 축. AGENTS.md 잠금 결정("금지어
후처리 필터 강제")과 직결되므로 **다른 4축과 달리 최저점(1점)이 곧 실격**이다.

| 점수 | 기준 |
|---|---|
| 1 | `safety.banned_words.BANNED_REPLACEMENTS` 원어가 치환 없이 그대로 출력됨("실패", "게으르", "한심", "포기", "패배" 등) — **실격**, 이 카드는 5축 합산과 무관하게 그 쌍대비교에서 자동 패배 |
| 2 | 금지어는 없지만 원인을 사람에게 귀속("당신이 ~해서") — 주어가 사람 |
| 3 | 원인 언급이 없어 안전하지만 상황 귀인으로도 안 감(중립적 사실 서술만) |
| 4 | 상황 탓으로 돌리되 자기자비 3요소(공통 인간성/판단 없는 수용/증진적 신념, 근거 A1) 중 1개만 있음 |
| 5 | 상황 탓("이 작업이 좀 컸던 것 같아요")이면서 자기자비 3요소 중 2개 이상, 자존감 부양("원래 잘하잖아요")은 없음 |

**자존감 부양 감점**: 5점 조건을 만족해도 능력/자질을 칭찬하는 문구("역시 잘하시네요",
"똑똑하시니까")가 있으면 4점을 넘지 못한다 — 근거 A1(자존감 조건이 자기자비 조건보다
약함, 229.9s vs 306.5s)과 §8-4(자존감 부양 문구 금지)가 이 상한의 근거다.

### ⑤ 사실 정합 (입력에 없는 사실 날조 없음)

| 점수 | 기준 |
|---|---|
| 1 | 컨텍스트에 없는 **구체적 사실**을 날조(없는 시간·장소·과거 이력을 확정적으로 언급) |
| 2 | 날조는 없으나 `strategy_group`이 지시한 방향과 다른 전략으로 답함(예: DOWNSCOPE 를 RESCHEDULE 문구로 답함) |
| 3 | 방향은 맞으나 `base_template`의 핵심 행동을 다른 걸로 바꿔치기 |
| 4 | 컨텍스트 안의 사실만 쓰고 방향도 맞으나, 애매한 표현("아마도", "보통")으로 얼버무림 |
| 5 | 주어진 컨텍스트 안의 사실만 쓰고, `strategy_group`의 방향(줄이기/미루기/이월/보류)을 그대로 유지 |

**구조적 노트**: `routes/recovery.py`가 이미 `strategy_code`로 게이트하지 않고 선두 카드에
직접 적용하는 방식으로 바꿔서(#57 이후) "LLM 이 다른 전략을 골라버리는" 사고 자체는 프로덕션
경로에서 이미 안 일어난다 — 그래도 심판 채점에서는 **텍스트가 실제로 그 방향을 지키는지**를
독립적으로 본다. 코드가 게이트하지 않는다는 것이 텍스트 품질이 좋다는 뜻은 아니다.

## 2. 종합 판정 — 승자 결정 규칙

1. 후보 A, B 각각 5축 점수를 합산(범위 5~25).
2. **축 ④가 1점(실격)인 후보는 합산 점수와 무관하게 그 비교에서 자동 패배.** 둘 다
   1점이면 무승부(§3).
3. 실격이 없으면 합산 점수가 높은 쪽이 승리.
4. **합산 동점이면 축 ④ 점수만으로 tiebreak**(L1-1 표에 이미 명시된 규칙 — 톤이 이
   시스템의 가장 강한 잠금 결정이라 동점 상황에서 우선한다).
5. 축 ④까지 동점이면 **무승부**로 기록한다(승패 어느 쪽에도 안 넣음).

**무승부의 승률 계산 처리**: pairwise 승률 = 승 / (승+패), 무승부는 분모·분자 모두에서
제외한다. 대안(무승부를 0.5승으로 반분)도 있으나, 이 실험의 표본(1,080건)에서 무승부가
드물 것으로 예상되고(5축 완전 동점은 흔치 않음), **제외가 "차이가 없다"를 "이겼다"로
슬쩍 세지 않는 더 보수적인 선택**이라 이쪽을 택한다 — 이 결정 자체가 설계자 판단이며,
분석 시점에 무승부 비율을 반드시 보고한다(비율이 10%를 넘으면 반분 방식과 비교해 결과가
바뀌는지 민감도 분석).

## 3. 심판 프롬프트 (LLM judge)

> ⚠️ **아직 실행 코드가 아니다.** 아래는 L1-1 하네스(1,080건 생성 + 1,440건 pairwise
> 판정, `docs/experiments/experiment-plan-v1.md` §2 L1-1)를 만들 때 그대로 옮길 **텍스트
> 명세**다. 실제 구현 시 이 프롬프트도 `prompts.registry`(8도메인 잠금, `SUPPORTED_DOMAINS`)
> 를 통과하지 않는다 — 프로덕션 사용자 호출이 아니라 오프라인 평가 도구이기 때문이다.
> 별도 스크립트(`scripts/` 또는 `eval/`)에서 직접 관리한다.

```
당신은 실행 코칭 카드의 품질을 채점하는 심사위원입니다. 아래 두 후보(A, B)는 같은
상황에 대해 서로 다른 방식으로 만들어진 if-then 코칭 카드입니다. 어느 쪽이 더 나은지
판단하지 말고, 각 후보를 5개 축에서 **독립적으로** 1~5점으로 채점하세요.

# 상황
- 실패 사유: {{failure_type}}
- 룰이 고른 전략: {{strategy_label}} (그룹: {{strategy_group}})
- 카탈로그 기본 문구: {{base_template}}
- 실행 컨텍스트: {{context_summary}}

# 후보 A
{{candidate_a_json}}

# 후보 B
{{candidate_b_json}}

# 채점 축 (각 1~5점, docs/experiments/rubric-v1.md §1 의 앵커를 그대로 적용)
1. if절 단서 구체성 — 시간/장소/직전 행동이 구체적인가. 날짜어("오늘"/"내일")가 있으면
   최대 3점.
2. then절 unpacking — 시간만 자른 게 아니라 식별 가능한 하위 단계로 나눴는가.
3. coping절 독립성 — then절과 다른, 장애물 대응이 있는가. then절의 재진술이면 4점을
   넘지 않는다.
4. 톤 — 아래 금지어가 치환 없이 그대로 있으면 1점(실격): 실패, 또 못, 안 됐, 못했,
   왜 안, 다시 실수, 게으르, 한심, 패배, 포기. 원인이 사람에게 귀속되면 2점. 상황 탓 +
   자기자비(공통 인간성/판단 없는 수용/증진적 신념)면 4~5점. 능력·자질 칭찬이 있으면
   4점을 넘지 않는다.
5. 사실 정합 — "실행 컨텍스트" 밖의 구체적 사실을 지어냈는가. 전략 그룹의 방향(줄이기/
   미루기/이월/보류)을 유지했는가.

# 출력 형식 (JSON, 다른 텍스트 금지)
{
  "candidate_a": {"axis1": <1-5>, "axis2": <1-5>, "axis3": <1-5>, "axis4": <1-5>, "axis5": <1-5>},
  "candidate_b": {"axis1": <1-5>, "axis2": <1-5>, "axis3": <1-5>, "axis4": <1-5>, "axis5": <1-5>},
  "axis4_disqualification_reason": "<A 또는 B 가 1점이면 어느 금지어가 걸렸는지, 아니면 null>"
}
```

**승자 산정은 심판이 하지 않는다** — §2 의 규칙을 분석 코드가 결정적으로 적용한다. 심판이
승자까지 같이 내면 "왜 이겼는지"와 "무엇을 몇 점 줬는지"가 서로 다른 답을 낼 위험이 있고
(LLM 이 점수와 결론을 따로 생성하면 논리적으로 안 맞을 수 있다), 승자 판정 로직을 코드에
고정해야 재현 가능하다.

---

## 4. 블라인딩 절차 (L1-1 표의 "절차를 사전등록에 명시" 이행)

1. **버전 은닉**: 심판에게 넘기는 JSON 에 `prompt_version`/`prompt_id`/파일 경로를 절대
   포함하지 않는다 — `candidate_a_json`/`candidate_b_json` 은 `RecoveryProposalLLM`(또는
   v3 확장) 스키마의 순수 출력 필드만 담는다.
2. **A/B 라벨 무작위화**: 어느 버전이 A 인지는 케이스마다(그리고 §L1-1 의 "양방향 제시"에
   따라 같은 쌍을 뒤집어서도) 난수로 정한다. 실행 시점에 시드를 고정해 재현 가능하게 하되,
   시드 값 자체는 사전등록에 커밋 해시로 남긴다.
3. **swap consistency 계산과의 연결**: 같은 쌍을 A/B 뒤집어 두 번 제시했을 때 승자가
   같으면 일치, 다르면 불일치 — 이 비율이 L1-1 의 position bias 지표다. 이 루브릭의 §2
   판정 규칙이 결정적(같은 입력 → 같은 출력)이므로, swap 으로 승자가 바뀐다면 그건
   **심판의 점수 자체가 제시 순서에 따라 달라졌다**는 뜻이다 — 축 채점에 순서 정보가
   새어 들어가지 않았는지 확인하는 것이 이 지표의 존재 이유.
4. **심판 모델 선정**: `docs/experiments/experiment-plan-v1.md` L1-1 각주 — 생성과 다른
   provider 는 AGENTS.md §8 "새 외부 의존성"에 걸려 팀 합의가 필요하다. 합의 전까지는
   같은 provider 의 다른 모델을 쓰고 self-enhancement bias 를 한계로 명시한다(§7 참고).

## 5. 알려진 한계 (정직 표기)

| 한계 | 영향 | 완화 |
|---|---|---|
| **self-enhancement bias** — 생성 모델과 심판 모델이 같은 provider(팀 합의 실패 시) | 심판이 자기 계열 모델의 출력을 과대평가할 수 있음 | L1-2 (judge–human κ) 로 인간 라벨과 대조. κ < 0.41 이면 L1-1 을 본문에서 부록으로 강등(계획서 L1-2 성공 기준) |
| **앵커의 경계 모호성** — 예: ②의 3점과 4점 차이("하위 단계 지목" 여부)는 완전히 이산적이지 않음 | 심판·사람 코더 간 재현성 저하 | L1-2 의 inter-coder κ(인간 2인) 가 이 문제의 정도를 먼저 드러낸다 — 낮으면 앵커 자체를 다음 버전에서 수정 |
| **v1/v2 는 coping_clause 필드가 없음** — 축 ③ 채점 시 구조화 필드가 아니라 `rationale` 텍스트를 대신 봐야 함 | v1/v2 가 축 ③에서 구조적으로 불리(필드가 없어 최대 3점대) | 의도된 것 — H1-1b("v2 의 이득은 coping_clause 가 걸리는 태그에서 특히 크다")가 정확히 이 비대칭을 검증 대상으로 삼는다. 불리함이 아니라 가설 그 자체 |
| **④가 실격 축이라 다른 4축의 정보가 버려짐** | 톤 위반 카드가 나머지 축에서 만점이어도 자동 패배 — "얼마나 실격인지"의 정도차가 승률에 안 드러남 | 발표 자료에는 실격률(축4=1점 비율)을 승률과 **별도로** 병기한다 — 두 수치를 하나로 뭉개면 "톤이 좋아져서 이겼다"와 "다른 축이 좋아져서 이겼다"가 구분 안 된다 |

## 6. 이 문서를 다시 열어야 하는 시점

- L1-2(judge–human κ)가 0.60 미만으로 나오면 → 이 문서 §1의 앵커 서술이 모호하다는 뜻.
  인간 코더 2인의 불일치 사례를 모아 앵커를 구체화한 v2 를 만든다.
- v3 프롬프트가 실제로 `obstacle`/`coping_clause` 필드를 갖게 되면 → §0의 "심판이 보는
  것" 스키마와 §3 심판 프롬프트의 `{{candidate_x_json}}` 예시에 그 필드를 반영한다.
- BCT 코드 원문 재대조(근거 대장 §4.2, CONSENSUS-7)가 끝나면 → 축 ②/③ 설명에 인용한
  BCT 코드(8.7, 1.2 등)를 재검증된 값으로 갱신한다.
