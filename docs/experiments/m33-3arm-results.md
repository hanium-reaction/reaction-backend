### 1.1 ⚠️ `A_none` 0.941 은 **L1-7A 기준선이 아니다** — 측정 지점이 다르다

[`l1-7-results.md`](l1-7-results.md) 는 같은 골든셋·같은 34케이스·같은 `repeat 0` 에 대해
**M26-core = 0.794 (27/34)** 를 보고한다. 0.941 과 나란히 읽으면 안 된다.

**채점 코드 차이가 아니다.** 두 원자료를 같은 코드(`scripts/l1_7_run.py::m26_core`)로,
기준일을 09-03·09-04 양쪽으로 바꿔 재집계해도 값이 그대로다. 두 문서 다 계산은 맞다.

| | M26-core | 실패 원인 지표 |
|---|---|---|
| L1-7A 저장분 | 0.794 (27/34) | m17 5 · m19 2 · m20 2 |
| M33 `A_none` 저장분 | 0.941 (32/34) | m20 2 |

**원인은 저장한 파이프라인 지점이다.** M17 은 「③층 보정 전 LLM 원안」에 대한 지표인데
([`experiment-plan-v1.md`](experiment-plan-v1.md) §5), M33 이 저장한 계획은 ③층을 이미
통과한 것이다.

```
밴드 밖 세션 길이를 가진 케이스     L1-7A 5/34   ·   M33 0/34
③층 확장 자리표시자가 있는 케이스   L1-7A 0/34   ·   M33 2/34
```

§3.3 이 arm 별 자리표시자 개수를 직접 세고 있는 것도 같은 사실의 다른 표현이다.

> ⚠️ **M33 데이터에서 M17 은 구조적으로 실패할 수 없다** — 0/34. M26-core 는 8개 지표의

**이것이 §1 의 Δ 를 무효화하지는 않는다.** 세 arm 을 **같은 방식으로** 재서 뺀 값이라
내부적으로 정합하다. 무효가 되는 것은 `A_none` 을 L1-7A 기준선으로 읽는 것뿐이다.

## 2. general 은 **처치 노출이 없었다**

`repeat 0` 34건 중 **반려 0건**이다.

설계 §1.1 이 못 박은 대로 **승인 케이스는 세 arm 이 같은 계획을 공유**한다. 재분해가
일어나지 않으므로 Δ 는 **정의상 전부 0** 이다.

> **34개 케이스의 Δ 가 모두 0 인 것은 관측이 아니라 항등식이다.**
> ④층이 발화하지 않았으므로 이 표본에는 비교할 처치가 없다.

CI `[0, 0]` 도 같은 이유로 **정밀도가 높은 것이 아니라 분산이 0인 상수 벡터**의 산물이다.
"효과가 0 임을 좁은 구간으로 확인했다" 로 읽으면 안 된다.

## 3. challenge 는 처치가 있었지만 endpoint 가 움직이지 않았다

`repeat 0` 16건 중 **반려 2건**(`chal-ehhe` · `chal-hhhh`). 두 건 모두 재분해가 실행됐고,
**세 arm 의 계획이 실제로 서로 달랐다**(계획 JSON 해시 A ≠ B ≠ C).

그런데 M26-core 판정은 바뀌지 않았다. 이유는 **반려 사유와 M26-core 실패 원인이 다른
축**이기 때문이다.

### 3.1 M26-core 는 무엇 때문에 실패했나

```
CORE_METRICS = (m17, m19, m20, m21, m22, m23, m24, m25)
```

`repeat 0` 실패 케이스의 원인 지표:

| | 실패 건수 | 원인 |
|---|---|---|
| general | 2/34 | **m20**(케이던스) 2건 |
| challenge | 8/16 | **m21**(배치) 8건 · **m20**(케이던스) 7건 |

**M26-core 에는 구체성·착수 가능성 같은 의미 품질 지표가 없다.**

### 3.2 검토기는 무엇을 지적했나

반려 9건(전 반복 합산)의 피드백은 8건이 같은 내용이다.

> "21~28회차 항목들의 제목이 다소 포괄적이에요"
> "이어지는 회차 항목들의 제목과 첫 단계가 다소 추상적이에요"

지목된 자리를 열면 이렇다(`chal-hhhh` repeat 0, `A_none`):

```
[19] 모의고사 오답 정리 및 취약점 최종 보완        120분   ← LLM 원안
[20] 최종 요약 노트 회독 및 마인드 컨트롤          90분   ← LLM 원안
[21] 정보처리기사 실기 합격 21회차               120분   ← extend_action_plan_to_horizon
[22] 정보처리기사 실기 합격 22회차               120분
 …   (28회차까지 동일 패턴)
```

**검토기가 반려한 대상은 ③층 `extend_action_plan_to_horizon` 이 만든 확장 구간이다.**

### 3.3 재분해는 그 구간을 되돌리지 못한다

재분해 뒤에도 **같은 확장 단계가 다시 실행**되므로 확장 구간이 다시 자리표시자로 덮인다.
반려 9건의 arm 별 자리표시자 개수:

| 케이스 | A_none | B_feedback | C_retry |
|---|---|---|---|
| `chal-ehhe` rep0 | 8/28 | 8/28 | 8/28 |
| `chal-hhhh` rep0 | 8/28 | 8/28 | 8/28 |
| `chal-eheh` rep1 | 7/27 | 8/28 | 8/28 |
| `chal-ehhe` rep1 | 8/28 | 8/28 | 8/28 |
| `chal-ehhh` rep1 | 8/28 | 7/27 | 8/28 |
| `chal-eheh` rep2 | 8/28 | 8/28 | 7/27 |

확장이 덜 필요해진 것이지 자리표시자가 구체화된 것이 아니다.

## 4. ⚠️ "검토기가 맞게 지적했다" 로 읽지 않는다

**현재 루브릭은 이 카드들을 의도적 정상 산물로 규정하고 반려를 금지한다.**

> | **정상** | `extend_action_plan_to_horizon` 이 만든 `N회차` 연속 세션 |
> "달리기 5회차" / "달리기 6회차" — **룰이 의도적으로 만든 것이다. 반려 금지** |
>
> ⚠️ **`N회차` 오탐이 이 유형의 최대 위험이다.** … 검토기에는 회차 세션을
> **결함 후보에서 제외**하도록 명시한다.
>
> — `rubric-first-plan-v1.md` §D1

> | **정상** | 이어가기 세션의 복귀 단서 |
> "지난 회차에서 이어서 5분만 시작하기" (룰 생성분 — **반려 금지**) |
>
> — 〃 §D2

따라서 이번 관측의 정확한 서술은 이것이다.

> **v3 검토기는 제품이 의도적으로 만드는 continuation 카드를 '구체성 결함' 으로 본다.**

이는 검토기의 정답 여부가 아니라 **제품 계약과 검토 계약의 충돌**이다.
어느 쪽이 옳은지는 이 데이터가 답하지 않는다.

**추가 확인**: 루브릭이 처방한 제외 조항이 **v3 프롬프트에 반영돼 있지 않다.**

```
plan_quality.v3.md          '회차' · '이어서' 언급  0건
plan_quality_eval.v4.md     〃                     1건
```

### 5.1 `busy-thin` 의 반려 사유

> "15분 미만으로 짧게 잡힌 세션들이 일부 있어요."

그 경우다. **정의상 오탐에 해당하는 반려가 실제로 관측됐다.**
