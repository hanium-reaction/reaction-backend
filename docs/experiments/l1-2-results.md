## 0. 한 줄 요약

**judge–human κ = 0.482 → 보조 지표 등급(0.41~0.60).** L1-1 승률(v3 vs v1 1.000)을
"인간 판단의 대리치"로 승격하기엔(κ≥0.61 필요) 못 미치지만, "완전히 못 믿는다"(κ<0.41)
수준도 아니다. **inter-coder κ 를 계산 못 해 이 등급 자체가 잠정**이다 — §4 참고.

## 1. 왜 계획서 원안과 다른가

계획서 L1-2(`experiment-plan-v1.md:85-93`)는 "코더 2인 + 중재 1인(최소 1인은 v3
작성자가 아님)"을 전제로, **inter-coder κ**(사람 2인 간 일치도)를 judge–human κ 보다
먼저 검사하도록 못박아 뒀다 — "인간끼리 낮으면 LLM 을 탓할 수 없다"는 이유다.

이 프로젝트는 1인 개발이라 그 전제를 그대로 못 지킨다. inter-coder κ 는 "두 사람"이
없으면 원리적으로 계산이 성립하지 않는다 — 계산량이나 시간의 문제가 아니라 통계량 자체가
정의되지 않는다. 사용자와 상의해([#277](https://github.com/hanium-reaction/reaction-backend/pull/277))
**judge–human κ 만 계산하는 축소판**으로 진행하기로 했다.

## 3. 결과

| 항목 | 값 |
|---|---|
| 사람 라벨 | 40건 |
| 원본 판정과 매칭 성공 | 40 / 40 (매칭 실패 0건) |
| 단순 일치율 (사람 승자 == 심판 승자) | **0.700** (28/40) |
| **judge–human κ (Cohen's, unweighted)** | **0.482** |
| inter-coder κ (사람 2인 일치도) | **N/A** — 1인 개발이라 원리적으로 계산 불가 |

### 해석 (계획서 3단계 등급, `scripts/l1_2_analyze.py` 그대로 적용)

| 구간 | 의미 |
|---|---|
| κ ≥ 0.61 | L1-1 승률을 인간 판단의 대리치로 서술 가능 |
| **0.41 ≤ κ < 0.61 (실측값 0.482 이 위치)** | **보조 지표로만 사용** |
| κ < 0.41 | L1-1 결과를 본문에서 부록으로 강등 |

## 4. 한계·유보 (정직 표기)

| 항목 | 상태 | 의미 |
|---|---|---|
| **inter-coder κ 선행 조건 미검증** | 계산 불가(1인) | 계획서 원안은 "인간끼리도 이
  일치하는가"를 먼저 보고 나서야 judge–human κ 를 해석하게 설계했다. 그 선행 조건을
  못 봤으므로, **κ=0.482 가 낮은 이유가 "LLM 심판이 부정확해서"인지 "이 판정 과제
  자체가 사람에게도 원래 애매해서"인지 이 데이터만으로는 못 가른다.** 후자라면 사람
  2인을 붙여도 inter-coder κ 가 비슷하게 낮게 나올 수 있다 — 그 경우 LLM 만 탓하는
  건 부당하다 |
| **라벨러가 v3 설계에서 독립적이지 않음** | 계획서 위반 | 계획서는 "최소 1인은 v3
  작성자가 아니어야 한다"를 명시했다. 이 실행의 유일한 라벨러는 v3 프롬프트 설계를
  전 과정 검토·승인한 사용자 본인이다 — 완전히 독립적인 제3자 라벨이 아니다 |
| **표본 40건, 계획서 원안(100건)의 40%** | 축소 | 통계적 검정력이 원안보다 낮다.
  κ 의 표준오차가 더 크다는 뜻 — 추가 라벨링(`--n` 으로 확장 가능)으로 좁힐 수 있다 |
| **swap consistency 없음** | 사람 라벨은 한 방향만 봄 | LLM 심판과 달리 사람 라벨은
  정방향/역방향 양쪽을 안 봤다(예산상 의도적 선택, `l1_2_label.py` 참고) — 사람 라벨
  자체의 위치 편향(position bias) 여부는 이 데이터로 확인 불가 |

**결론적으로**: κ=0.482 는 "L1-1 이 순수 self-enhancement bias 로 부풀려진 착시"라는
가설도, "L1-1 이 인간 판단과 거의 완벽히 일치한다"는 가설도 둘 다 확정적으로 지지하지
않는다. 두 가설 사이 어딘가에 있고, 이 문서의 데이터만으로는 더 좁힐 수 없다.

## 5. L1-1 결과에 대한 영향

[`l1-1-results.md`](l1-1-results.md) §0/§7 을 이 결과로 갱신했다:

- **이전 서술**: "self-enhancement bias 를 아직 배제하지 못했다(L1-2 미실시)"
- **갱신된 서술**: "judge–human κ=0.482(보조 지표 등급) — L1-1 승률(1.000)을 인간
  판단의 대리치로 쓸 근거는 아직 부족하다. **보조 지표로 취급하고, 본문 핵심 결론은
  아니다.**"

⚠️ **이 문장은 낡았다.** 작성 시점(2026-08-20)에는 `_PROMPT_ID` 가 `@v2` 하나였으나, 현재 프로덕션은 **`AVOIDANCE` 태그에 한해 v3** 를 쓴다(`api/routes/recovery.py:117-119, 387-388`). **전면 승격은 여전히 안 했고**, 그 판단의 근거가 이 문서의 κ=0.482 다 — 자세한 것은 [`l1-1-results.md`](l1-1-results.md) §다음 단계 2번.

## 6. 다음 단계

1. **추가 라벨링** — `uv run python -m scripts.l1_2_label --n 60` 으로 표본을 100건까지
   늘리면 κ 추정이 더 안정된다(이미 라벨링한 40건은 자동으로 건너뜀).
2. **inter-coder κ 확보** — 팀원이 합류하면(또는 외부 검토자를 구하면) 같은 표본을
   독립적으로 한 번 더 라벨링해 계획서 원안의 선행 조건을 채울 수 있다.
3. **테스트-재검사(test-retest)** — 2번이 여의치 않으면, 같은 라벨러가 시간을 두고
   같은 표본 일부를 다시 라벨링해 자기 일관성(self-consistency)이라도 확인하는 게
   차선책이다 — inter-coder κ 의 완전한 대체는 아니지만 "이 과제가 사람에게도
   애매한가"에 대한 부분적 신호는 준다. 이번 실행 범위에는 포함하지 않았다.

## 7. 재현 방법

```bash
# 1) 라벨링 (대화형, 사용자 본인이 직접 실행 — 자동화 불가)
uv run python -m scripts.l1_2_label

# 2) 분석 (LLM 호출 없음, 순수 계산)
uv run python -m scripts.l1_2_analyze
```

표본 추출은 `SAMPLE_SEED` 로 재현 가능하지만, 사람의 채점 자체는 라벨러마다·시점마다
달라질 수 있어 κ 수치가 재현되지는 않는다.
