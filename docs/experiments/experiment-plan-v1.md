> 작성 2026-08-17 · 짝 문서: [`docs/research/recovery-evidence-base.md`](../research/recovery-evidence-base.md)

## 0. 설계 원칙

**"참가자 수에 의존하지 않는 증거부터 쌓는다."**
학생 팀 실험이 무너지는 지점은 항상 같다 — 참가자를 못 구해서 아무것도 못 싣는 것. 그래서 3층으로 나누고, **아래 두 층만으로도 보고서가 완성되게** 설계한다.

| 층 | 참가자 | 무엇을 증명하나 | 무너져도 되나 |
|---|---|---|---|
| **L1 오프라인 평가** | **0명** | 프롬프트·룰엔진·시스템 품질을 **숫자로** 비교했다 | ❌ 절대 안 됨. 여기가 본체 |
| **L2 워크스루·전문가 평가** | 3~8명 (팀+지인) | 설계 결함을 **구조적으로** 찾아냈다 | ⚠️ 축소 가능 |
| **L3 현장 실험** | 10~30명 | 실제 사용자에서 **추정치와 실현가능성**을 얻었다 | ✅ 무너져도 보고서는 선다 |

**현실적 절단선(권고)**: 8주 안에 확실히 되는 것은 **L1 전체 + L2-1/L2-3/L2-5 + 재설계 중 S난이도 항목 구현 + L3-1 단일 실험(4주)** 이다. 나머지는 "후속 과제"로 명시한다. 아래 §7 타임라인은 이 절단선을 기준으로 짰다.

### 0.1 정직성 규칙 4개 (사전 고정)

1. **지표 정의는 이 문서에만 있다.** 분석 시점에 정의를 손대면 p-hacking이다.
2. **분석 코드는 데이터 수집 시작 전에 더미 데이터로 검증**해 둔다.
3. **중간 점검에서 결과 지표를 보지 않는다.** 보는 것은 결손률·배정 비율·크래시뿐. **단 안전 감시는 이 규칙의 예외다**(§8.2).
4. **대조군은 "아무것도 안 함"이 아니라 "카탈로그 템플릿(기존 fallback 경로)"** 이다. 근거: Adriaanse et al. 2011 — 통제조건이 부실할수록 효과가 부풀려진다(저자 명시).

## 2. L1 — 오프라인 평가 (사람 0명, 오늘 시작 가능)

### L1-0. 골든셋 사양 — 120건

| 블록 | 건수 | 구성 |
|---|---|---|
| 단일 태그 정상 | 13태그 × 4 = **52** | 태그당 짧은/긴 카드 × 오전/야간 블록 |
| 복합 태그 | 13 × 2 = **26** | 실제 로그에서 흔한 2태그 조합 (예: FATIGUE+PLAN_TOO_BIG) |
| 미매칭 3태그 보강 | 3 × 4 = **12** | TIME_SHORTAGE / OVERRUN / AVOIDANCE |
| 경계·분기 | **20** | overwhelm 3/4/5 경계, 연속실패 2/3/5회, EMERGENCY, abandoned 직후, 23시 근접, 신규 유저 |
| **적대적(톤 위반 유발)** | **10** | "제가 원래 게으른 편이라" 같은 자기비난 회고 — **LLM 이 동조/아첨하는지** 본다 |
| **합계** | **120** | |

- 저장: `eval/golden_recovery_cases.jsonl`
- **입력 출처를 반드시 표기**: 실 로그가 부족하므로 (a) 팀 도그푸딩 로그 + (b) 페르소나 합성. **합성 비율을 보고서에 쓴다.**
- ⚠️ **블라인딩**: 정답 라벨("기대 그룹")을 설계자가 쓰고 설계자가 만든 룰 엔진을 채점하면 자기충족적이다. → 정답 라벨은 **설계에 관여하지 않은 1인**(멘토 또는 FE 담당)이 작성하거나, "정답"이 아니라 **"설계 의도"** 로 재명명하고 정확도 지표에서 뺀다.

### L1-1. 프롬프트 v1 vs v2 vs v3 — 문구 품질

| 항목 | 내용 |
|---|---|
| **가설** | H1-1: v3 > v2 > v1 순으로 LLM 심판 pairwise 승률이 높다. H1-1b: v2 의 이득은 **coping_clause 가 걸리는 태그**(DISTRACTION, AVOIDANCE, CONTEXT_LOSS)에서 특히 크다 |
| **조작** | 프롬프트 파일만 교체. 룰엔진·카탈로그·모델·temperature 고정. 120건 × 3버전 × 3반복 = **1,080 출력** |
| **1차 지표** | **pairwise 승률.** 루브릭 5축 각 1–5점: ① if절 단서 구체성 ② then절 unpacking(축소판이 아닌가) ③ coping절 독립성(then 반복이 아닌가) ④ 톤(주어가 사람이 아닌가) ⑤ 사실 정합(입력에 없는 사실 날조 없음). 동률 시 ④로 tiebreak |
| **분석** | 3쌍 × 120건 × **양방향 제시** = 1,440 판정. **swap consistency**(순서 뒤집어도 승자 유지 비율)를 position bias 지표로 **반드시 병기**. CI 는 **케이스 단위 클러스터 부트스트랩**(1,440건은 독립 베르누이가 아니다 — 케이스를 리샘플한다) |
| **블라인딩** | 파일명·메타에서 버전 제거, 제시 순서 무작위화. 절차를 사전등록에 명시 |
| **성공 기준** | ① v3 vs v1 승률 ≥ 0.65 **AND** 부트스트랩 하한 > 0.50 ② swap consistency ≥ 0.80 ③ 어떤 태그 층에서도 v3 승률 0.35 미만 없음 |
| **실패 시 해석** | 승률이 0.5 근처면 → **"문구 개인화의 이득은 문구 품질 축에서 검출되지 않음"**. 이는 Milkman et al. 2022(22개 문구 간 격차 ≈0.9%p)와 **정합적**이며 "LLM 개인화보다 타이밍·구조가 큰 레버"라는 서사로 전환한다. swap consistency < 0.70 이면 심판을 신뢰할 수 없으므로 승률 수치를 폐기 |
| **소요 / 담당** | 3일 / BE-1(생성), BE-2(심판·통계) |

⚠️ **심판 모델**: "생성과 다른 provider"는 AGENTS.md §8(새 외부 의존성)에 걸린다 → **팀 합의 항목**. 합의 실패 시 같은 provider 의 다른 모델을 쓰고 **"self-enhancement bias 를 완전히 배제하지 못함"을 한계로 명시**한다.

### L1-2. LLM 심판 ↔ 인간 라벨 일치도

| 항목 | 내용 |
|---|---|
| **가설** | H1-2: LLM 심판 판정이 인간 2인 합의 라벨과 **Cohen's κ ≥ 0.61** 로 일치한다 |
| **1차 지표** | judge–human κ. **단, inter-coder κ(인간 2인)를 먼저 보고한다** — 인간끼리 낮으면 LLM 을 탓할 수 없다 |
| **성공 기준** | inter-coder κ ≥ 0.60 **선행 조건**. 그 위에서 judge–human κ ≥ 0.61 이면 L1-1 승률을 "인간 판단의 대리치"로 서술 가능. 0.41–0.60 이면 보조 지표로만. < 0.41 이면 **L1-1 을 본문에서 부록으로 강등** |
| **실패 시 해석** | Zheng et al. 의 80%+ 일치는 **영어·개방형·쌍대선호** 조건 값이다. 한국어 회복 코칭 절대채점으로 전이된다는 근거가 없다. **낮게 나오는 것이 정상 가능 결과이고, 그걸 보고하는 것 자체가 차별점**이다 |
| **소요 / 담당** | 4일 / 코더 2인 + 중재 1인 (**셋 중 최소 1인은 v3 작성자가 아니어야 한다**) |

### L1-3. 룰 엔진 커버리지 — **검정 없이, 전수 카운트로**

| 항목 | 내용 |
|---|---|
| **가설** | H1-3: 신규 전략 4종 + 태그 확장 후 **패딩 노출률이 감소한다**(방향: 감소) |
| ⚠️ **삭제한 가설** | "커버리지 10/13 → 13/13" 은 태그를 `primary_trigger_tags` 에 넣는 순간 참이 되는 **동어반복**이다. 가설이 아니라 작업 확인이므로 결과 표에만 싣는다 |
| **1차 지표** | **패딩 노출률** = (선택 카드 중 `primary_trigger_tags ∩ 입력 태그 = ∅` 인 카드) / 전체 선택 카드. 골든셋 120건 **전수** |
| **분석** | ⚠️ **유의성 검정 금지.** `select_strategies` 는 세션 없는 **결정적 순수 함수**다(`orchestrator/recovery.py:54`) — 같은 입력에 같은 출력이라 표본 추출 오차가 없다. McNemar 를 돌리면 "표본이 무엇이냐"는 질문 하나에 무너진다. → **전수 카운트 + 케이스 목록**(120건 중 패딩 n건, 어느 태그에서)으로 보고 |
| **구조적 한계 (미리 적을 것)** | `MIN_CARDS = 2` 때문에 매칭 그룹이 1개면 **패딩이 강제된다**(`recovery.py:89`). 단일 태그 케이스 52건은 구조적으로 패딩을 유발하므로 "≤5%" 같은 기준은 커버리지와 무관하게 실패할 수 있다. → 목표는 절대값이 아니라 **감소폭**으로 잡고, `MIN_CARDS` 는 별도 UX 안건으로 올린다 |
| **가드 테스트** | 카탈로그에서 태그 1개를 **일부러 제거한 fixture** 로 테스트가 **빨강**인지 확인한다. 정상 데이터만 읽는 테스트는 `if False:` 로 바꿔도 초록이다 |
| **SQL** | JSONB 이므로 `&&` 가 아니라 `?` — [근거 대장 §7.3-1](../research/recovery-evidence-base.md) 참조 |
| **소요 / 담당** | 2일 / BE-1(시드·핀), BE-2(히트맵) |

### L1-4. 시스템 지표 — fallback / p95 / 비용

| 항목 | 내용 |
|---|---|
| **선행** | **P9 (timeout 8 vs 12) 확정 후 시작.** 기준선이 흔들리면 결과가 무의미하다 |
| **가설** | H1-4: v2·v3 는 출력 필드가 늘어 p95 지연·토큰이 증가하지만, **fallback rate 증가폭은 5%p 이내** |
| **조작** | 3버전 × 120건 × 5회 = **1,800 호출**. 동일 시간대 **인터리브** 실행(시간대 교란 차단) |
| **1차 지표** | **fallback rate 를 원인별 3분해**: timeout / 형식검증 실패 / 톤게이트 거부. 현재 `llm_fallback_used` 불리언 하나로는 분해 불가 → ✅ `llm_runs.reason`(이미 있던 컬럼)에 `"tone_gate"` 값 추가로 해소 — **별도 `tone_gate_rejected` 컬럼은 안 만듦**(중복 컬럼이 갈라질 위험, `report_llm_run_metrics.py` 참고) |
| **⚠️ 지표 정의 정정** | 지연은 "호출당"이 아니라 **"카드 1장 완성까지의 end-to-end (재생성 포함)"** 로 측정한다. 톤 게이트 재생성이 동기 재호출이면 최악 2배가 요청 경로에 들어가는데, 단발 호출만 재면 통과해도 프로덕션 p95 를 보증하지 못한다 |
| **데이터 출처** | **`llm_runs` (이미 존재)** — `prompt_version, latency_ms, tokens_in, tokens_out, cost_micro_usd, success, fell_back`. 신규 테이블 불필요 |
| **성공 기준** | ① p95 ≤ 확정 예산의 80% ② fallback rate ≤ 12%, timeout 기여 ≤ 8%p ③ 요청당 비용 증가 ≤ 40% |
| **실패 시 해석** | p95 초과 시 v3 보류하고 **coping_clause 만 남긴 v2 를 배포 후보로 확정**한다. 또는 acknowledgment 를 **서버 템플릿으로 prepend** 해 토큰을 아낀다. **"전부 넣기"가 아니라 "예산 안에서 고르기"가 설계 결정임을 보고서에 쓴다** |

### L1-5. 지표 재정의 회귀 시뮬레이션 (기존 로그 재계산)

### L1-7. 첫 계획(First Plan) 품질 — 준수도와 검토기 (오프라인)

L1-6 은 **자료를 따르는가**만 덮는다. 계획이 **사용자가 인터뷰에서 직접 말한 제약을
지키는가**, 그리고 그걸 심사하는 **LLM 검토기(`planning/plan_quality`)가 제 역할을 하는가**
는 잴 자가 없었다. 후자는 이미 실측 사고가 코드 주석에 남아 있다 — 사용자가 세션 길이를
120분이라 답해 분해가 120분 세션을 만들자 **검토기가 3/3 반려했고 재분해가 60분으로 줄였다**
(`orchestrator/first_plan.py::_review_variables` 주석). 사용자가 명시한 값이 조용히 절반이
됐고 계획 총량도 반토막 났다. 이 실험은 그 사건을 지표로 재현·일반화한다.

> **짝 문서: [`rubric-first-plan-v1.md`](rubric-first-plan-v1.md)** — 결함 5종의 정의·앵커,
> 층 분업 규칙, 결함 주입 사양, `plan_quality_eval.v4` 출력 계약이 거기 있다. **"결함이란
> 무엇인가"는 그 문서가 단일 진실 소스**이고 여기서 재정의하지 않는다.

**측정 지점 — 파이프라인 4층 중 ②③④**

```
① validate_inputs         룰 게이트(Focus<=3 / Maintain<=5). 잠금 결정이라 측정 대상 아님
② decompose_goal          LLM 원안                        <- L1-7A 의 측정 대상
③ shape_action_plan 계열   결정적 룰 보정                   <- 정답 역할(sound verifier)
④ review_plan             LLM 검토기 -> 재분해(<=2회)       <- L1-7B 의 측정 대상
```

#### L1-7A. 계획 준수도 — 룰이 정답이므로 정답 라벨이 필요 없다

| 항목 | 내용 |
|---|---|
| **가설** | H1-7A: LLM 분해 원안은 사용자가 명시한 제약(세션 길이·주당 분량·빈도)을 상당 비율로 벗어나며, 그 이탈을 ③층 결정적 보정이 흡수하고 있다. 즉 **현재 계획 품질의 상당 부분은 LLM 이 아니라 룰이 만들고 있다** |
| **조작** | 없음(관찰). 골든셋 케이스를 프로덕션과 같은 분해 경로에 태우고, ③층 보정 **전/후**를 둘 다 기록해 차이를 센다 |
| **1차 지표** | **M26** `first_plan_pass_rate` — 그룹 A 전 항목을 **한 계획 안에서 동시에** 통과한 비율 |
| **보조 지표** | M17~M25. **전부 micro/macro 이중 집계** (§5 참조) |
| **데이터 출처** | `eval/golden_first_plan_cases.jsonl`(신규) — 생성기 `scripts/build_golden_first_plan_cases.py`. 하네스 `scripts/l1_7_run.py` |
| ⚠️ **왜 정답 라벨이 없어도 되는가** | 정답이 설계자가 아니라 **사용자가 인터뷰에서 답한 값**이다(`session_length` / `weekly_hours` / `frequency_per_week` / `horizon`). `eval/README.md` 가 회복 골든셋에서 경계한 "설계 의도를 정확도로 쓰면 자기충족적" 문제를 원리적으로 피한다. ACPBench(AAAI'25)가 *"정답 계획이 여러 개일 수 있는 도메인에서는 계획 자체를 평가하기 어렵다"* 며 계획 채점을 포기하고 원자 과제로 쪼갠 것과 대비되는 지점이다 |
| ⚠️ **그 이점의 절반은 문제가 쉬워서다** | TravelPlanner(ICML'24)가 어려운 이유는 제약이 **조합적으로 상호작용**하기 때문이다(예산 × 도시간 이동 × 최소숙박일수). 우리 그룹 A 는 대부분 제약을 **하나씩 독립 체크**한다. 보고서에서 "정답 없이 평가 가능"을 설계의 공으로만 돌리지 않는다 |
| ⚠️ **구조적 결함 탐지 != 예측 타당도** | DCMA 14-point(미 국방부 계약관리국 일정 품질 검사)에 대해 스케줄링 실무 문헌이 다는 경고를 그대로 물려받는다 — **전 항목을 통과해도 그 일정이 달성 가능하다는 보장은 없다.** M17~M26 이 전부 좋아도 "계획이 실제로 지켜진다"는 뜻이 아니다 |
| **성공 기준 (1차 실행)** | **기준선 수립이 목표다.** 절대 임계값을 사전 고정하지 않는다 — 이 축의 기준선이 레포에 없다. 다만 방향성 기준 2개는 미리 건다: ① `normal` 블록의 M26 을 **보고 가능한 수치로 산출**할 것 ② M24(범위 이탈)는 ADR-0007 실측(2주기 12세션 중 9~12번이 다음 마일스톤 구간)을 **before 기준선**으로 삼아 현재 값이 그보다 낮음을 보일 것 |
| **참고 대조점** | TravelPlanner Final Pass Rate: GPT-4-Turbo **4.4%**(sole-planning) / GPT-3.5-Turbo 0.6% / Gemini Pro 2.1%. 우리 M26 이 낮게 나오는 것 자체는 이 계열 과제의 정상 범위다 — **낮은 수치를 실패로 읽지 않기 위한 대조점으로 반드시 병기한다** |
| **실패 시 해석** | M17·M18 이 높으면(=원안이 이미 제약을 지킴) ③층 보정은 안전망일 뿐이고 개선 여지는 프롬프트가 아니라 다른 데 있다. 낮으면 **분해 프롬프트가 사용자 값을 못 지키고 있다**는 직접 증거이므로 프롬프트 개선의 1순위 근거가 된다 |
| **알려진 한계** | 합성 케이스라 실사용자 인터뷰 결과의 분포를 대표하지 않는다. 특히 `session_length` 미답 경로가 실사용에서 얼마나 흔한지 모른다 |
| **소요 / 담당** | 골든셋 1일 + 하네스 2일 / BE |

#### L1-7B. 검토기(Plan Verifier) — 분류기로 측정한다

⚠️ **`approved` 비율을 계획 품질 지표로 쓰지 않는다.** 검토기가 자기 판정으로 자기를
채점하는 구조가 되어 무의미하다. 검토기는 **측정 도구가 아니라 측정 대상**이다.

| 항목 | 내용 |
|---|---|
| **가설** | H1-7B: **LLM 검토기 층(④)은 순이득이 아닐 수 있다.** 구체적으로 ① 무결함 계획을 반려하고(오탐) ② 재분해가 지적과 무관한 사용자 명시값을 파괴하며 ③ 재분해의 개선분은 피드백 내용이 아니라 **단순 재시도**에서 온다 |
| ⚠️ **선행 발견 — v3 체크리스트 1·2번은 오탐 생성기다** | 슬롯 조합 **1,620건 전수 확인**: ③층 `normalize_action_minutes` 의 상한이 ④층에 넘기는 `focus_capacity` 와 **같은 함수**(`session_min_for`)라, 검토기가 볼 때 상한 초과는 **0/1,620 — 구조적으로 발화 불가**하다. 즉 그 항목의 모든 반려는 정의상 오탐이고, **120분 사고는 우발적 오작동이 아니라 그 항목이 있는 한 반드시 나는 사고**였다. 15분 하한도 90/1,620 에서 남는데 전부 룰이 **의도적으로 허용**한 조합이다. → 두 항목은 "기준을 다듬을" 대상이 아니라 **삭제 대상**이며, 그 근거로 v4 에는 `focus_capacity` 변수 자체를 넘기지 않는다 ([루브릭 §1](rubric-first-plan-v1.md)) |
| **조작** | 결함 주입(seeded defect) — 무결함 계획 하나를 고정하고 결함 **1종만** 결정적으로 심는다. 결함 유형은 [루브릭 §2](rubric-first-plan-v1.md) 의 D1~D5 |
| **1차 지표** | **M33** `verifier_lift_vs_none` — ④층을 **끈** 계획 대비 그룹 A 지표 개선폭 |
| **보조 지표** | M27a 반려율 · **M27b recall** · M27gap(틀린 이유로 반려) · M28a 유형지목 · M28b localization · **M29 false_reject_rate** · M30 repair · M31 collateral · M32 self-consistency · **M34** `feedback_lift_vs_retry` |
| **대조군 1 — ④층 제거** | `review_plan` 을 끄고 ③층만으로 만든 계획. **이게 없으면 "검토기를 개선했다"까지만 말할 수 있고 "검토기가 필요한가"에 답을 못 한다.** 우리는 ③층에 이미 결정적 검증기를 갖고 있어 이 비교가 가능하다 — LLM-Modulo(ICML'24)가 권하는 구조가 정확히 "생성은 LLM, 검증은 sound verifier" 다 |
| **대조군 2 — "그냥 다시 해봐"** | 반려는 시키되 `review_feedback` 을 비운 재분해. 근거: Stechly et al. 이 **상세 피드백과 최소 피드백("다시 해봐")의 결과가 거의 같음**을 보고했다 — 개선이 비평 내용이 아니라 재샘플링에서 왔다는 뜻이다. 이 대조군 없이 M30 을 재면 **재시도 효과를 검토기 공로로 착각**한다. 구현 비용은 문자열 하나를 비우는 것 |
| **문헌 근거 — 우리 사고는 예외가 아니다** | ① Valmeekam et al. 2023: downstream 성공률 **LLM+VAL(기호적) 59% vs LLM+LLM self-critique 41%** ② Kambhampati & Valmeekam, LLM-Modulo(ICML'24): 자기비평 루프가 baseline 보다 **나빠질 수 있다** — *"시스템이 정답을 정답으로 인식하지 못해, 운 좋게 맞았던 답을 걸러내고 결국 오답으로 끝난다"* ③ Huang et al.(ICLR'24) *LLMs Cannot Self-Correct Reasoning Yet*: 외부 신호 없는 자기수정은 정확도를 **떨어뜨린다** ④ *When Can LLMs Actually Correct Their Own Mistakes?*(TACL'24): 많은 자기수정 논문이 **정답에만 수정을 적용하도록 설계해 오답 전환 비용을 구조적으로 은폐**한다. 우리가 M29 를 최우선 감시로 두는 것은 이 지적의 정면 대응이다 |
| **성공 기준 (1차 실행)** | ① **M33 의 부호를 결정할 것** — 양수면 ④층 유지, 0 이하면 ④층 제거 또는 룰 대체를 설계 안건으로 올린다 ② **M29 <= 0.10** (이 축은 방향이 이미 확정적이라 유일하게 절대 임계값을 사전에 건다) ③ M34 로 피드백의 순기여를 분리해 보고할 것 |
| **경계값 격자 필수** | 사고가 난 120분은 결함이 아니라 **사용자 상한에 정확히 붙은 정당한 값**이었다. 결함 1종 주입으로는 경계 근처 반려율 급등을 못 본다 → `constraint_edge` 블록을 상한 ±5분 격자(예 115/120/125)로 구성해 **반려율 곡선**을 그린다 |
| **반복 필수** | 케이스마다 **N >= 3 회** 반복해 M32 를 낸다. 우리 "3/3 반려" 는 케이스 1건이라 체계적 편향인지 노이즈인지 아직 못 가른다. 근거: *Reliability without Validity*(21개 모델·9개 제공사·약 54.1만 판정)의 최소 검증 프로토콜 |
| ⚠️ **단순 일치율 보고 금지** | 같은 논문 실측: **raw agreement 가 chance-corrected kappa 를 MT-Bench 기준 평균 38.6%p 과대평가**한다(JudgeBench 23.7%p, RewardBench 10.4%p). 사람 라벨과 대조할 때는 반드시 kappa/alpha 로 보고한다. position bias 도 모델별 0.002~0.192 로 **100배 편차** — 범용 안전값이 없으므로 우리 모델에서 직접 잰다 |
| ⚠️ **승인율 상승을 수렴 증거로 쓰지 않는다** | 반복 자기개선 실험에서 **심판 점수는 라운드마다 오르는데 사람 점수는 정체·하락**했고(4~5라운드에서 격차 뚜렷), 원인은 심판과 생성자의 컨텍스트 공유였다. **우리 재분해 루프가 정확히 그 구조다** |
| ⚠️ **결함 설계의 순환성** | 체크리스트를 쓴 사람이 심을 결함도 고르면 "자기가 만든 버그만 잡는 린터"가 되어, **아무도 예상 못한 실패 유형은 영원히 측정되지 않는다.** 완화책 2개를 적용한다(**둘 다 집행됨 2026-08-31**): ① 체크리스트 작성자와 **다른 모델이 결함을 설계**(held-out fault design) — 앵커 표·주입 레시피를 가리고 D1~D5 한 줄 정의만 준다. 조건은 [`eval/first_plan_seeded_defects.json`](../../eval/first_plan_seeded_defects.json) 의 `provenance` 에 남고, 그 설계자가 되돌려준 **분류 체계의 빈칸 3개**는 [루브릭 §6](rubric-first-plan-v1.md) 에 기록했다 ② 합성 규칙보다 **실제 인시던트에서 결함 패턴을 채굴** — 우리는 120분 사고 · `_WAITING_TITLE_RE` 백스톱이 생긴 사고(#225) · ADR-0007 범위 이탈 실측이 이미 있어 이 길이 가장 값싸다 |
| ⚠️ **시딩 유효성 자체가 논쟁 중이다** | Just et al.(FSE 2014)은 뮤테이션 점수와 실결함 탐지율의 강한 상관을 보고했지만, 후속 ICSE 2018 은 그 관계가 테스트 스위트 크기 등에 교란된다며 회의적이다. **양쪽을 병기한다** |
| **운영점 보고** | 현재 검토기는 이진 `{approved, feedback}` 만 반환해 PR curve 를 못 그린다. 심각도 점수를 노출하도록 바꾸면 **"M29 <= 0.10 제약 하 최대 recall"** 형태로 운영점을 고를 수 있다. F-beta 를 쓴다면 beta = sqrt(cost_FN / cost_FP) 이므로 우리는 beta < 1(정밀도 편중). ⚠️ **ROC-AUC 와 accuracy 는 쓰지 않는다** — 무결함 케이스가 압도적으로 많아 낙관적으로 보인다 |
| **실패 시 해석** | M33 <= 0 이면 결론은 "검토기 프롬프트를 더 다듬자"가 아니라 **"이 층을 룰로 대체하거나 걷어내자"** 다. 문헌이 반복해서 도달한 결론이고, 우리는 대체할 룰 층(③)을 이미 갖고 있다 |
| **알려진 한계** | 심은 결함은 실제 결함보다 **탐지하기 쉬운 쪽으로 편향**된다(단일 지점 수정, 의미적 단순성). M27a·M27b 를 실사용 결함 검출률로 읽지 않는다. 그리고 유형별로 **남은 지름길**이 있다 — `eval/README.md` 「M27·M28 을 읽을 때」 |
| **소요 / 담당** | 결함 골든셋 1일 + 하네스 2일 + 대조군 실행 1일 / BE |

과대주장하지 않기 위해 **확립된 것과 우리 확장을 구분해 적는다.**

#### 파생 설계 안건 (이 실험 밖, 이슈로 올린다)

1. **`plan_quality` 체크리스트에서 "SMART" 인용을 뺀다.** 근거가 탄탄한 것은 Locke & Latham 의
   *"구체적이고 도전적인 목표"* — 즉 **S 하나**다. SMART 5글자를 하나로 묶어 채점하는 검증된
   도구는 서베이 범위에서 발견되지 않았고, Bjerke & Renger(2017)는 baseline 없이 A·T 판정이
   불가능하다고 비판한다. → **Sniehotta action planning scale 의 문항 차원**(when / where /
   how / how often / with whom)으로 대체한다. M20 이 이미 *how often* 에 대응하고,
   **where·how 는 우리 지표에 없는데 예측 증거가 있는 축**이라 보류 결정을 재검토할 근거가 된다.
   → **이미 반영됐다**: [루브릭 §2 D2](rubric-first-plan-v1.md) 가 SMART 항목을 이 차원으로 대체했다.
2. **반려 피드백을 외부 아티팩트로 전달한다.** 동일한 오류 지적이라도 **모델 자기 출력 안에
   있으면 교정률 0~17%**, 같은 내용을 외부 역할(도구 응답·사용자 메시지)로 재라벨링하면
   **+53~87%p** 상승한다는 실측이 있다. 지금 `_replan_feedback` 은 산문 리스트를 같은
   프롬프트에 다시 얹는다 → 구조화된 JSON diff / 도구 응답 형식으로 바꾸는 것은 싸고
   M30·M34 로 효과를 검증할 수 있는 변경이다.
3. **배치 최적성 지표(2차).** 제약을 다 만족해도 세션이 파편화되거나 마감 직전에 몰린 배치는
   그룹 A 에서 만점이 나온다. 결정적 정의가 필요해 이번 범위 밖으로 미룬다.
4. **재계획 지속 여부(L3 층).** 1개월 시점 목표 실패의 최강 예측자가 초기 계획 품질이 아니라
   **"새 계획을 세우지 않음"(OR=7.54)** 이었다는 보고가 있다(구체성 OR=4.59 보다 크다).
   우리 제품엔 주간 재계획이 이미 있으므로, first plan 품질만 재고 이 축을 안 재면 더 큰
   레버를 놓친다. **L1 이 아니라 관찰/L3 층 지표**라 여기서는 지표 사전에만 예약한다.

#### 인용 검증 상태 (보고서에 숫자로 박기 전 확인)

- ✅ **확인됨**: Valmeekam 59% vs 41% · TravelPlanner Final Pass Rate 표 · LlamaGuard/ShieldGemma FPR ·
  *Reliability without Validity* 의 38.6%p / position bias 0.002~0.192 · Sniehotta beta=.26 ·
  Just et al. FSE 2014 · ACPBench 인용문
- ⚠️ **원문 표 대조 필요**: Huang et al. 의 GSM8K/CommonSenseQA 하락 수치 · Stechly 의

  일치하나, 수치 인용은 PDF 원문 표 확인 후에 한다.**

## 4. L3 — 현장 실험 (참가자 10~30명)

### L3-0. 설계 형태와 표본 근거 — **여기가 방어의 핵심**

**설계**: **참가자 내(within-subject) 무작위화.** 회복 카드가 생성되는 각 시점에서 문구 레이어를 무작위 배정.
**배정 단위**: 카드 단건이 아니라 **주 단위 블록**으로 배정한다.
> **왜 주 단위인가**: LLM arm 에서 coping plan 형식과 단서 고르는 법을 배운 사용자는 다음 template arm 에서도 그 형식을 스스로 적용한다(**학습 이월 = 오염**). 카드 단위로 섞으면 효과가 하향 편향된다. 주 단위 블록은 이월 노출을 줄이고, 모형에 "직전 주 arm" 항을 넣어 잔여 이월을 통제한다.

**표본 크기 — 정직한 계산**

⚠️ **초안의 설계효과 공식 `DE = 1 + (m−1)·ICC` 는 이 설계에 쓰면 안 된다.** 그 공식은 **클러스터(사람) 단위로 처치를 배정할 때**의 분산 팽창이다. 처치가 참가자 **내부**에서 갈리면 사용자 수준 상관은 처치 대비에서 상당 부분 상쇄되어 분산 계수는 팽창이 아니라 대략 `(1−ICC)` 방향으로 간다. 그 공식을 쓰면 MDE 를 **약 6배 과대 계상**하게 되고, "우리는 검정력이 없다"는 겸손한 결론이 **틀린 산수 위에 서게 된다** — 심사에서는 겸손이 아니라 통계 미숙으로 읽힌다.

**대신 이렇게 한다:**
1. **실현 결정시점부터 계산한다.**
   `실현 결정시점 = N × 주당 실패 건수 × 수집 주수 × 적격률 × 잔존율`
   각 계수는 **가정값을 표에 명시**한다(예: 주당 실패 4건, 4주, 적격률 0.8, 4주 잔존 0.7).
2. **검정력은 공식이 아니라 시뮬레이션으로** 낸다 — 더미 로그로 혼합효과 로지스틱을 1,000회 돌리면 반나절이면 끝난다. 이게 F19(MDE 표)의 근거가 된다.
3. **기간·잔존율을 문서 전체에서 하나로 통일한다** (본 계획: **수집 4주**).

| N | 실현 결정시점(가정 명시) | 이 규모에서 할 수 있는 말 |
|---|---|---|
| **≥ 20** | ~360건 | 추정치 + CI. "검정"이라는 단어는 1차 지표 1개에만 |
| **12–19** | ~215건 | 추정치 + CI만. 하위집단 분석 금지 |
| **≤ 11** | ~125건 | **"실현가능성 연구"로 재라벨.** 개인 단위 N-of-1 시리즈로 전환 |
| **≤ 5** | — | L3 폐기, L1+L2 로 보고서 완성 |

### L3-1. 회복 문구 레이어 A/B (**유일한 주 실험**)

| 항목 | 내용 |
|---|---|
| **가설** | H3-1: LLM 개인화 if-then + coping plan 카드를 받은 실패 건은 카탈로그 템플릿 카드를 받은 건보다 **72시간 내 회복 완주율이 높다** |
| **조작** | arm A = 카탈로그 템플릿(기존 fallback 경로) / arm B = LLM v3 (acknowledgment 조건부 + coping clause). **주 단위 블록 배정** |
| **1차 지표** | **`recovery_followthrough_72h`** — 회복 카드가 **표시된**(`first_viewed_at IS NOT NULL`) 실패 건 중 그룹별 성공 정의(§5 M2)를 72시간 내 충족한 비율 |

| **분석** | 참가자 랜덤절편 혼합효과 로지스틱. 고정효과 = arm + 주차 + **직전 주 arm(이월 통제)**. ITT |

| **성공 기준** | ⚠️ "OR > 1.2 면 성공" 같은 **오차 통제 없는 임의 컷은 쓰지 않는다.** 점추정 + 95% CI 만 보고. 확증 프레임에 두는 것은 **1차 지표 1개뿐**이고 2차는 전부 표에 **"탐색적"으로 태깅** |
| **기간 / 담당** | 4주 / BE-2(분석), PM(운영) |

### L3-2. 재알림 마이크로 무작위화 — **조건부 실행**

⚠️ **초안대로는 불가능하다.** 세 겹으로 막힌다:
1. `NOTIFICATION_CLASSES` 는 3종이고 **DB CHECK 제약**까지 걸려 있다. 목록 밖 클래스는 `ValueError`.
2. `PUSH_WEEKLY_BUDGET = 3` 은 **전 클래스 합산 rolling 7일**이다. 신규 넛지가 예산을 먹으면 그날 저녁 회고 푸시가 막히고, **회고가 안 열리면 회복 카드 자체가 생성되지 않는다** → 한 실험의 처치가 다른 실험의 표본을 파괴한다.
3. 예산 차단은 무작위가 아니라 **이력 의존**이므로 사후 층화하면 편향된다.

**실행 조건 (전부 충족 시에만)**: P7(알림 대상·열람 로깅) 완료 + 기존 `pre_card` 클래스 **안에서** 발송/미발송을 무작위화(클래스 신설 0, 예산 소모 동일) + `evening_reflection` 을 예산에서 **우선 예약**하는 규칙 선행.
**대안(권고)**: 푸시가 아니라 **인앱 배지**로 내리고 가설을 "인앱 큐의 근접 효과"로 바꾼다.
**공통 필수**: `push_gate` 차단 사유(`quiet_hours`/`class_dedup`/`weekly_budget`)를 **결정시점 로그에 사유별로 남기고**, 보내지 않은 것도 기록한다.

### L3-3. 관찰 연구 (실험 아님 — 기술 통계)

이탈 곡선(Kaplan-Meier), 사전/사후 척도(SUS, UES-SF, SCS-SF), 종료 인터뷰.
⚠️ **SCS-SF 를 arm 간 비교에 쓰지 않는다** — 참가자 내 배정이라 두 arm 이 같은 사람에게 걸리므로 arm 차이로 귀속되지 않는다. **기술 통계로만.**

> #### 주지표를 **둘로 나눈다** — M26-core 와 M18

> M26 전체를 흔든다.**

> **나란히 보고한다.** "별도 보고" 로 밀어두지 않는다 — 둘 다 주지표다. M26-core 만 좋고
> M18 이 나쁘면 그것이 결론이고(이번 실측이 정확히 그렇다), 그 조합을 한 숫자로 뭉개면
> 정보가 사라진다.
>
> #### 항목별 통과 조건 (M26-core) — **유도 / 선택 / 카브아웃을 구분해 표시한다**
>
> | 지표 | 통과 조건 | 성격 |
> |---|---|---|
> | **M17** | 밴드 밖 leaf **0건** | **유도** — §5 의 macro 정의("그 계획에 위반이 한 건도 없는가")에서 나온다. 밴드는 룰(`session_min_for`)이 정한다 |
> | **M19** | `_take_within_budget` 이 잘라낸 leaf **0건** | **유도** — 〃 |
> | **M20** | `실제 주당 세션 ≥ frequency_per_week` (**슬랙 없음**) | **선택** — 프로덕션의 `0.8` 슬랙을 **일부러 안 쓴다.** 그 값은 사용자를 덜 성가시게 하려는 UX 값이고, 지표는 "사용자가 말한 빈도를 맞췄나" 를 물어야 한다. **더 엄격한 쪽을 골랐다** |
> | **M21** | `_UNPLACED_MARKER` **0건** | **유도** — 못 놓은 세션은 이견 없이 실패다 |
> | **M22** | `마지막 계획일 ≥ min(마감, 지평 상한)` (**슬랙 없음**) | **선택** — `horizon_coverage_notice` 를 쓰지 않는다(위 오용). 덮어야 할 날을 **지평 상한으로 자른** 뒤 비교한다 |
> | **M23** | 마일스톤 **있으면** `missing_milestone_titles` 빈 목록 · **없으면 N/A** | **유도** + **조건부 적용**(아래) |
> | **M24** | `drop_out_of_cycle_branches` 가 걷어낸 branch **0건** | **유도** + 카브아웃 |
> | **M25** | `_WAITING_TITLE_RE` 백스톱이 잡은 leaf **0건** | **유도** — 〃 |
>
> **M26-core = 위 8개의 AND.** 정직한 셈: **유도 6 · 선택 2.**
>
> #### M18 — 가드레일로 보고하고, 임계값은 **제품 정책**이라 지금 정하지 않는다
>
> 초판의 반-세션 규칙(`|총 분 − 예산| ≤ planned_session_min_for / 2`)은 **유도가 아니었다.**
>
> - M18 은 **③층 보정 전 원안**에서 재는데 원안은 LLM 이 만든 임의의 `estimated_minutes` 다.
>   "계획은 세션 단위로만 만들어진다" 가 성립하지 않는다 — 성립하면 M17 이 자명하게 100% 다
> - **보정 후에도 성립하지 않는다.** leaf 길이는 `planned_session_min_for` 의 정수배로
>   만들어지지 않는다. `normalize_action_minutes` 는 **`[15분, 집중용량]` 밴드로 클램프만**
>   하고, ADR-0009 D2 가 *"평균을 상한으로 쓰면 길이가 내용을 따라갈 수 없다"* 며
>   **일부러 입도를 없앴다.** 즉 그 밴드는 수학적 필연이 아니다
> - 실측: 밴드 폭 = 1/(2N) 이라 골든셋에서 **1.79% ~ 6.25%, 3.5배 차이**. 그 차이는
>   `_MAX_LLM_SESSIONS` 캡과 지평 주수에서 오는 것이라 **계획 품질과 무관**하다
>
> **따라서 M18 의 임계값은 팀이 고르는 제품 정책이다.** 그리고 **지금 관측한 데이터로 그
> 정책을 확정하면 안 된다** — 그게 §0.1 규칙 1번이 막는 것이다.
>
> **그때까지 M18 은 이렇게 보고한다** (임계값 없이도 완전히 계산된다):
>
> ```
> M18a  중앙값 · 사분위 · 최소/최대 · <1.0 / =1.0 / >1.0 건수   (프롬프트 지시 대비)
> M18b  〃                                                      (최종 예산 대비)
> ```
>
> ⚠️ **M19 가 M18 의 위쪽을 이미 막는다.** `_take_within_budget` 은 누적 분이 예산을 1분이라도
> 넘으면 자르므로 예산 초과 계획은 **M26-core 의 M19 에서 탈락**한다. 정책을 정할 때 이
> 상호작용을 함께 봐야 한다 — 양방향 밴드를 걸면 위쪽 절반이 죽은 규칙이 된다.
>
> #### 계산 불가 처리 — **"해당 없음" 과 "미측정" 은 다르다**
>
> 초판은 둘을 뭉쳐 *"한 지표라도 계산 불가인 케이스는 M26 분모에서 뺀다"* 고 적었다.
> 그대로 적용하면 M26 분모가 34 → **6** 이 된다(마일스톤 케이스만 남는다). **셋으로 나눈다.**
>
> | 상태 | 뜻 | M26-core 처리 |
> |---|---|---|
> | **통과 / 실패** | 조건이 적용되고 판정됐다 | AND 에 들어간다 |
> | **N/A (해당 없음)** | 사용자에게 **요구된 것 자체가 없다** | **중립** — AND 에서 빠지고, 케이스는 분모에 **남는다** |
> | **미측정** | 잴 수단이 없다(도구 부재) | **M26-core 를 산출하지 않는다** |
>
> **이 구분이 이 절에서 가장 중요하다.** 마일스톤이 없는 28건은 데이터가 빠진 게 아니라
> **애초에 지킬 마일스톤이 없다.** 그걸 실패로 세면 부당하고, 케이스를 통째로 빼면
> **M26 이 사실상 마일스톤 6건만의 지표**가 된다.
>
> | 지표 | N/A 조건 | 골든셋 |
> |---|---|---|
> | **M22** | 마감이 지평 상한 **밖** — 시스템이 **의도적으로** 안 덮는다 | 23/34 이 N/A |
> | **M23** | 이번 주기 확정 마일스톤이 **없다** | **28/34 이 N/A** (적용 6건) |
> | **M24** | 창이 남은 마일스톤 **전부를 덮는다** — 이탈이 원리적으로 불가능 | 하네스 `m24_measurable` |
>
> ⚠️ **보고서에는 지표마다 "적용 사례 수" 를 반드시 병기한다.** M23 이 6건에서만 적용됐다는
> 사실 없이 "M23 통과율 1.00" 을 실으면 독자가 34건으로 읽는다.
>
> ⚠️ **초판의 M24 카브아웃 조건 `can_refill`(빈도 명시) 은 틀렸다.** 골든셋 34건 **전부**
> `frequency_per_week` 를 갖고 있어 **한 건도 못 걷어낸다.** [`l1-7-results.md`](l1-7-results.md)
> §2.3 이 M24 분모를 42 → 24 로 줄인 실제 조건은 **창 커버리지**였다.
>
> #### M20·M21·M22 는 진짜 "미측정" 이다
>
> 스케줄러를 안 돌려 배치 결과가 없다. **N/A 가 아니라 도구 부재**이므로, 이 셋이 채워지기
> 전에는 **M26-core 를 산출하지 않는다.** 부분 집합의 AND 를 M26-core 라 부르지 않는다.
>
> #### 반복 3회 집계 — **초판에 없던 자유도**
>
> §5 의 M26 분모는 "케이스 수"(34)인데 실행은 34 × 3 = **102 계획**을 낸다. 접는 방법을
> 안 정하면 지표가 크게 움직인다 — [`l1-7-results.md`](l1-7-results.md) §4 가
> **"34개 중 10개가 회차마다 M17 통과/실패가 갈린다"**(우연 기대 12.1) 고 적었다.
>
> **등록: 1차 추정은 `PRIMARY_REPEAT = 0` 의 고유 34건.** M26-core 와 M18 둘 다 같은 규칙을
> 쓴다. L1-7B 가 M29 에 쓰는 것과 같다 — 반복을 독립 표본으로 세면 신뢰구간이 거짓으로
> 좁아진다. 회차별 세 값과 "3회 모두 통과" 비율은 **보조로 함께** 낸다(그건 주지표가 아니다).
>
> #### 두 주지표를 내려면 아직 남은 것
>
> | 주지표 | 막는 것 | 상태 |
> |---|---|---|
> | **M26-core** | **배치 경로와 분해 하네스가 아직 따로 돈다** — 두 결과를 **한 계획 위에서** 합쳐야 AND 가 성립한다 | ⬜ **유일한 blocker (배선)** |
> | **M18** | 없음 — 임계값 없이 분포로 보고하면 **지금 나온다** | ✅ [`l1-7-results.md`](l1-7-results.md) §2.1 |
>
> ✅ **초판이 blocker 로 적었던 것은 전부 해소됐다.** ① L1-7A v2 재실행 완료(#417)
> ② M23 분모 0 은 blocker 가 아니라 **N/A 처리 대상**이었다(위 표) ③ M18 임계값은
> M26-core 에서 뺐다 ④ **M20·M21·M22 는 이제 계산된다**(#418 배치 경로).
>
> **남은 것은 지표 문제가 아니라 배선이다.** `scripts/l1_7_schedule_eval.py`(배치)와
> `scripts/l1_7_run.py`(분해)가 따로 돌아, M17~M25 를 **같은 계획 위에서** 내려면 두 경로를
> 합쳐야 한다. 지금 합치면 AND 가 서로 다른 계획을 섞는다.
>
> **두 경로가 합쳐지기 전에는 M26-core 를 내지 않는다.** 분해 하네스가 계산하는 것은
> **M17·M18a·M18b·M19·M23·M24·M25** 다.
>
> #### M33 과의 관계
>
> **M33 = ΔM26-core 다** (M18 은 AND 에서 빠졌으므로). 위 blocker 를 그대로 이어받는다. 추가로:
>
> - **arm 은 셋이다** (④층 제거 · 피드백 비운 재분해 · 정상). 초판은 "두 arm" 이라 적었다.
> - **같은 기준만으로 부족하고 같은 분모가 필요하다.** 어떤 케이스가 한 arm 에서만 N/A 가
>   되면 ΔM26-core 가 **서로 다른 케이스 집합의 차**가 된다. 페어링을 강제한다.
> - **M18 은 M33 에 안 들어간다.** 대신 arm 별 M18 분포를 나란히 싣는다 — ④층이 분량을
>   어느 쪽으로 밀었는지가 그 자체로 결과다.
> - ⚠️ **바닥 효과 경고.** M26-core 가 두 arm 모두 바닥에 깔리면 ΔM26-core 의 부호를 결정할 수 없고,
>   §2 L1-7B 의 성공 기준 ①("M33 의 부호를 결정할 것")이 그대로 무너진다. M26-core 가 실제로
>   0 근처로 나오면 **M33 을 그대로 밀지 말고 지표 설계를 다시 본다.**

**M17~M26 은 micro / macro 를 **둘 다** 보고한다** (L1-7A). micro = 항목 단위(세션 100개 중 95개가 밴드 안), macro = 계획 단위 전부-통과(그 계획에 위반이 한 건도 없는가). 사용자에게는 **한 건이라도 어긋나면 어긋난 계획**이므로 micro 만 보고하면 실제 체감보다 좋아 보인다. 근거: TravelPlanner 가 모든 제약 지표를 micro/macro 두 벌로 보고하는 관행. M26 은 그 macro 를 전 지표에 걸쳐 합친 최상위 한 줄이다.

⚠️ **게이밍 경로 고지**: 제약 통과율은 **계획을 적게 내면 올라간다**(위반할 대상 자체가 줄어든다). TravelPlanner 가 Delivery Rate 를 Pass Rate 와 분리 보고하는 이유가 이것이다. 우리는 M19(절단)·M21(배치)·**M18 을 양방향으로** 읽어 이 경로를 막는다 — M18 이 1.0 미만이면 "제약을 지킨 것"이 아니라 **과소 생성**으로 읽는다.

⚠️ **계측 구멍 (M17~M19 선행 조건)**: `decompose_goal` 은 `goal_plan` 을 보정 체인마다 덮어써서 **③층 보정 전 원안이 남지 않는다**(`first_plan.py:426-475`). 단 `drop_waiting_steps`→`waiting_dropped`, `drop_out_of_cycle_branches`→`out_of_cycle_dropped`, `extend_action_plan_to_horizon`→`coverage_extended` 는 **이미 상태에 남으므로 M24·M25 는 지금도 집계 가능**하다. 구멍은 `normalize_action_minutes`(길이 클램프)와 `_take_within_budget`(분량 절단) **두 개뿐**이다. 오프라인 하네스는 함수를 순서대로 직접 호출해 우회하고, **라이브 로그로 같은 지표를 보려면 그때 카운터를 추가**한다.

⚠️ **M9(p95)는 LLM 계획 벤치마크의 관행이 아니다** — 그쪽은 대개 평균 추론시간·비용만 보고한다. tail latency 는 SRE 관행에서 수입한 것이며, 사용자가 버튼 하나를 누르고 기다리는 제품이라 평균으로는 체감을 보증하지 못하기 때문이다. 보고서에 이 사실을 각주로 밝힌다.

**계산 불가 판정 (정직 표기)**: M12 는 P7 없이 계산 불가. "알림 후 앱 오픈" 계열은 **P8(세션 이력)** 없이 계산 불가 → 해당 지표를 사전등록에서 **삭제**하고 보고서에 "계측 부재로 미측정"으로 쓴다.

**핵심 SQL 은 [근거 대장 §7.3](../research/recovery-evidence-base.md) 에 검증본이 있다** — 여기서 재정의하지 않는다.

## 8. 윤리 · 안전

### 8.1 필수 게이트

- **IRB 면제/간이 여부 회신을 W4 게이트의 필수 항목으로 둔다.** 문의만 보내고 회신 전에 수집을 시작하는 경로를 막는다. SCS-SF 같은 심리 척도를 반복 투여하면서 "면제일 것"이라는 자체 판단으로 시작하면, 결과가 좋아도 발표·게재에서 통째로 폐기된다.
- **동의 취득자와 분석자·인터뷰어를 분리한다.** 모집이 지인 네트워크이고 PM 이 동의·인터뷰·매핑을 겸하면 거절의 자유가 형식적이다.

### 8.2 취약군 보호 — 초안에서 고친 것

⚠️ **초안의 L3-2(자기연민 acknowledgment 실험)는 `overwhelm ≥ 4` 또는 AVOIDANCE, 즉 가장 취약한 층에서만 지지 문구를 무작위로 제거하는 설계였다.** 그런데 우리 설계 자체가 바로 그 조건을 acknowledgment 가 **필요한** 조건으로 정의했다. 즉 **열등 처치임을 알면서 취약군에 배정**하는 구조다.
→ **폐기하거나**, `ack_off` 를 "무처치"가 아니라 **"중립적 사실 인정 1문장"**으로 바꾼다. 그러면 비교가 "자기연민 vs 중립 인정"이 되어 Breines & Chen 의 실제 대비(자기자비 vs 자존감 vs 무처치)와도 더 맞는다.

### 8.3 안전 감시 (효능 분석과 분리)

- **담당자 1인**을 지정한다. peeking 금지는 **효능 엿보기 금지이지 이상반응 감시 면제가 아니다.**
- **사전 정의 중단 규칙**: 임의 참가자가 ① 연속 abandoned 5회 ② overwhelm 5 를 3일 연속 ③ 자기비난 텍스트 급증 → **개인별 실험 중단 + 수동 연락**.
- L4 stand-down 대상을 "사전 정의된 비적격"으로 제외하면 **해악이 가장 잘 보일 층이 데이터에서 구조적으로 사라진다** → 제외하되 **별도로 기술 통계는 남긴다**.

## 9. 참가자를 못 구했을 때

### 9.1 N ≤ 11 이면

**버리는 것**: L3-1 의 "검정" 지위(OR·CI 는 보고하되 "차이가 있었다/없었다"라고 쓰지 않는다) · 집단 수준 KPI 비교 · 모든 하위집단 분석.
**대체하는 것**:
1. **N-of-1 시리즈로 전환.** 참가자 각각을 개별 사례로 보고하고 F16(개인별 시계열)이 주 그림이 된다. 참가자별 Tau-U 를 나열하고 시리즈 합산치 병기 — **Tau-U 변형(기저선 추세 보정 여부)과 계산 도구를 반드시 명시**해야 재현 불가 비판을 피한다.
2. **정성 비중 확대**: 전원 20분 반구조화 인터뷰(10명 = 3.3시간). 고정 질문 5개 — ① 가장 도움된 카드와 이유 ② 무시한 카드와 이유 ③ **문구가 비난처럼 느껴진 순간** ④ 알림 타이밍 ⑤ 다시 쓸 것인가.
3. **서사 전환**: "효과 검증"이 아니라 **"무작위 배정·결정시점 로깅 파이프라인이 현장에서 결손률 X% 로 작동함을 실증하고, 다음 규모 실험을 위한 ICC 와 기저율을 확보했다"**.

### 9.2 소표본에서 정직하게 쓸 수 있는 주장 수위

| | 표현 | N=10 |
|---|---|---|
| ❌ | "회복 카드가 재실행률을 X% 높였다" | 절대 금지 |
| ❌ | "자기연민 문구가 효과적임을 확인했다" | 절대 금지 |
| ❌ | "유의하지 않았으므로 효과가 없다" | 금지 — **검정력 부재를 무효과로 오독** |
| ✅ | "관측된 회복 완주율은 X%(95% CI …)였고 문헌의 Y% 와 같은 범위였다" | 허용 |
| ✅ | "무작위 배정·로깅 파이프라인이 결손률 Z% 로 작동함을 확인했다" | 허용(실현가능성) |
| ✅ | "10명 중 7명에서 수락률과 완주율의 갭이 20%p 이상 관측되었다" | 허용(개인 단위 카운트) |
| ✅ | **"본 규모에서 검출 가능한 최소 효과는 X%p 이며, 문헌적 기대 효과(2~18%p)를 상회한다. 따라서 본 연구의 목적은 효과 검증이 아니라 추정치 산출과 실현가능성 확인이다"** | **허용이자 권장 — 이 문장이 심사 방어의 핵심** |

> **핵심 원칙**: 소표본에서 신뢰를 얻는 길은 "약한 증거를 강하게 말하기"가 아니라 **"내 증거의 한계를 심사위원보다 먼저 정확히 계산해 제시하기"** 다. **MDE·검정력 표(F18)를 결과 절 맨 앞에 배치한다.**

## 10. 보고서 「한계」 절 초안

> 본 연구의 표본은 N=__ 로, 사전 검정력 시뮬레이션 결과 검출 가능한 최소 효과는 __%p 였다. 이는 문헌이 보고하는 유사 개입의 효과 크기(문자 리마인더 +2.0%p, 맥락 맞춤 알림 +14%)를 크게 상회하므로, **본 연구는 효과 검증이 아니라 추정치 산출과 실현가능성 확인을 목적으로 한다.** 유의하지 않은 결과를 "효과 없음"으로 해석해서는 안 된다.
> 참가자 내 무작위화 설계는 **학습 이월(carryover)** 에 취약하다. LLM 개인화 조건에서 습득한 계획 형식을 통제 조건에서도 적용할 수 있어 처치 효과가 **하향 편향**될 수 있다. 주 단위 블록 배정과 직전 주 arm 항으로 완화했으나 완전히 제거하지는 못했다.
> 골든셋은 실 로그 부족으로 __% 가 합성 데이터이며, 기대 라벨은 설계 참여자가 작성했다(일부는 외부 1인 검토). 룰 엔진 평가에는 **자기충족적 요소**가 남아 있다.
> LLM 심판의 인간 라벨 대비 일치도는 κ=__ 였다. Zheng et al.(2023)의 80%+ 일치는 영어·개방형·쌍대선호 조건의 값이며 한국어 회복 코칭의 절대채점으로 전이된다는 근거는 없다.
> 신규 도입 기간의 **참신성 효과(novelty effect)** 와 연구 참여 자체의 효과는 통제하지 못했다. 관측 기간이 4주로 짧아 장기 지속에 대해서는 어떤 주장도 하지 않는다.
> 다수의 2차 지표는 다중비교를 통제하지 않았으므로 **전부 탐색적**이며, 확증적 해석은 사전 지정한 1차 지표 1개에 한정한다.
