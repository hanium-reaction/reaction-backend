## 0. 이 실행이 잰 것 — 정확히 이 문장이다

> **스케줄러 충돌 정보가 없는 조건에서, 현재 프로덕션 `plan_quality.v3` 가, ③층 보정을
> 거쳐 이미 정상인 계획을 얼마나 잘못 반려하는가.**

"검토기 층 일반" 의 성능이 아니다. 범위 한계는 §5 에 따로 적는다.

**가장 강하게 말할 수 있는 결론:**

> 현재 v3 는 이 고정 골든셋에서 **정상 대조군 30건 중 1건을 반려**했고, **결함 easy 10건
> 중 3건만 반려**했다. **M29 ≤ 0.10 은 확인하지 못했다.** D1 의 2/2 반려는 알려진 지름길
> 때문에 의미 이해의 증거로 해석하지 않는다.

## 1. 표본 단위 — 먼저 고정하고 시작했다

| 지표 | 분모 | 단위 |
|---|---|---|
| **M29** `false_reject_rate` | 무결함 대조군 30건 | **사전 지정된 1회 호출**(`PRIMARY_REPEAT = 0`) |
| **M27a** `verifier_rejection_rate` | 심은 결함 20건 — 유형별 | 〃 |
| **M32** `verifier_self_consistency` | 케이스당 판정 쌍 | 3회 전부 |
| `any_of_3_reject_rate` | 대조군 30건 | **보조 — M29 가 아니다** |

⚠️ **반복 3회를 150개 독립 표본으로 세지 않았다.** 같은 케이스의 반복은 상관이 있어
신뢰구간이 거짓으로 좁아진다. `PRIMARY_REPEAT` 는 코드 상수로 **사전 지정**돼 있다 —
결과를 보고 회차를 고르는 일이 없게.

## 2. M29 — 사전등록 임계값을 **확인하지 못했다**

```
오반려          1/30 = 0.033
단측 95% 상한   0.149        ← Clopper-Pearson (정확값, 근사 아님)
사전등록 기준   ≤ 0.10       → **확인 실패**
반려된 대조군   control-mixed-lengths
```

점추정 3.3% 는 임계값 아래지만, **상한이 0.149 라 "≤0.10 을 만족한다" 고 말할 수 없다.**

### 2.1 이것은 실패가 아니라 기준을 지킨 결과다

대조군 30건은 **0건 반려일 때만** 임계값을 확인할 수 있는 크기였다(0/30 → 상한 0.095).
1건이 나온 순간 상한이 0.149 로 올라간다.

⚠️ **여기서 대조군을 60건으로 늘리지 않는다.** 1/30 을 보고 나서 상한을 낮추려고 표본을
더하면 **결과를 본 뒤 표본 크기를 조정**하는 것이 된다. 추가가 필요하면 새 대조군과 표본
수를 **사전 고정한 별도 v3 확인 실험**으로 한다.

### 2.2 반려된 케이스

`control-mixed-lengths` — **15분짜리 확인 작업과 긴 초안이 한 계획에 섞인** 정상 계획이다.
루브릭 §3 이 회귀 속성 `mixed_lengths` 로 일부러 넣어둔 케이스이고, "v3 가 정상 편차를
반려한다" 를 잡으려던 자리다. 그 자리에서 실제로 반려가 났다.

## 3. M27a — 유형별 반려율

**repeat 0, 유형별.** easy 의 정답은 반려, boundary 의 정답은 통과다.

| 유형 | easy 반려 (정답=반려) | boundary 반려 (정답=통과) |
|---|---|---|
| **D1** 중복 | **2/2** | 0/2 ✓ |
| **D2** 착수 불가 | **0/2** | 0/2 ✓ |
| **D3** 순서 역전 | **0/2** | 0/2 ✓ |
| **D4** 착수 단서 부재 | **0/2** | 0/2 ✓ |
| **D5** 목표 무관 | 1/2 | 0/2 ✓ |
| **합계** | **3/10** | **0/10** |

⚠️ **"v3 가 D1 을 이해해 탐지했다" 로 읽지 않는다.** `eval/README.md` 「M27·M28 을 읽을
때」가 남은 지름길을 유형별로 적어 두었다. 말할 수 있는 것은 **"이 고정 골든셋에서
반려했다"** 까지다. 그리고 n=2 다.

⚠️ **다만 D2 는 반대 방향으로 읽을 수 있다.** D2 에는 `마저` 라는 완전 분리자가 있는데
(무결함 대조군 30건에서 발화 0건) **그런데도 0/2 다.** 지름길로 맞힐 수 있었는데 안
맞혔다는 뜻이므로, D2 의 0/2 는 지름길 경고와 무관하게 읽어도 된다.

## 4. M32 — 판정 일관성

```
쌍 일치          144/150 = 0.960
판정이 갈린 케이스  3/50 = 0.060
```

⚠️ **0.960 을 "판정이 안정적" 으로 읽으면 안 된다.** 분포를 보면 이유가 분명하다:

| | 건수 |
|---|---|
| 3회 **모두 승인** | **45 / 50** |
| 3회 모두 반려 | 2 / 50 |
| 판정이 갈림 | 3 / 50 |

**승인 편향 자체가 pairwise agreement 를 밀어 올린다.** 대부분 승인이면 쌍은 자동으로
일치한다. 정확한 서술은 **"144/150 쌍이 일치했고, 실제로 판정이 갈린 것은 3건이었다"** 다.

### 4.1 갈린 3건

| 케이스 | 블록 | 정답 | 성격 |
|---|---|---|---|
| `control-mixed-lengths` | 무결함 대조군 | 통과 | **오탐 쪽**에서 흔들림 |
| `d2-easy-cert` | 심은 결함 D2 easy | 반려 | **미탐 쪽**에서 흔들림 |
| `d5-easy-cert` | 심은 결함 D5 easy | 반려 | 〃 |

⚠️ **이 셋을 "경계 사례" 라고 부르면 틀린다.** 뒤의 둘은 `easy` 결함이다(골든셋에서
`boundary` 는 정답이 통과인 별도 레벨이다). **"결정이 갈린 사례"** 로만 부른다.

## 5. 범위 한계 — **보고서에 반드시 함께 싣는다**

### 5.1 현행 v3 한정이다

v3 는 루브릭 §1.2 가 **④층에 넘기지 말라고 규정한** `focus_capacity`·`session_length` 를
받는다. 이 하네스는 그것을 **일부러 그대로 넘긴다** — 빼면 재려던 것(현행 설계의 오탐
비용)을 못 잰다. 따라서 이 수치는 **"검토기 층 일반" 의 성능이 아니다.**

### 5.2 스케줄러 충돌 정보가 없다

하네스는 배치를 돌리지 않으므로 `conflict_report="(없음)"` 로 호출한다. 즉 이것은 완전한
운영 파이프라인이 아니라 **"스케줄러 충돌 정보가 없는 조건에서의 v3 단독 판정"** 이다.

루브릭 §1.2 는 충돌을 **검사 항목이 아니라 전달 항목**으로 규정하므로 그것이 반려 근거가
되면 안 된다는 설계는 맞다. **그러나 LLM 이 그 문맥에 영향받지 않는다는 보장은 없다.**

### 5.3 그 외

- **전 케이스 합성이다.** 실사용 계획 분포를 대표하지 않는다.
- **유형별 n=2 다.** M27a 의 어떤 칸도 단독으로 성능 주장을 받칠 수 없다.
- **남은 지름길 9건과 M28 위치 누출 6건**이 그대로다 — `eval/README.md` 참조.
- **M27b·M27gap·M28a·M28b 는 못 냈다.** v3 는 `{approved, feedback: list[str]}` 뿐이라
  자유 문장을 기계가 못 센다. `plan_quality.v4` 가 있어야 한다.
- **M33·M34·재분해 축(M30·M31)은 이 실행에 없다.** 대조군 arm(④층 제거 · 피드백 비운
  재분해)을 안 돌렸다.
- **3반복은 같은 날·같은 모델 버전·같은 설정**이고 시드 통제가 없다.

## 6. 관찰 — 단정하지 않고 적는다

**이 표본에서는 미탐 신호가 더 강하다.** 대조군 30건 중 1건 반려, 결함 easy 10건 중 3건
반려. D2·D3·D4 는 0/2 다.

⚠️ **"v3 의 문제는 오탐이 아니라 미탐이다" 로 단정하지 않는다.** M29 도 기준 확인에
실패했다(상한 0.149). 두 축 모두 이 표본으로는 결론이 안 난다 — 다만 **관측된 신호의
방향이 미탐 쪽**이라는 것까지가 지금 말할 수 있는 전부다.

이것이 v4 설계의 근거로 쓰일 때 주의할 점은 §7 에 적는다.
