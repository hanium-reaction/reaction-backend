# L0 결과 — 자료 조사 소스는 목차와 분량을 주는가

> **설계 가정이 틀렸음을 확인한 스파이크.** 알라딘 `OptResult=Toc` 로 도서 목차를 받는다는
> 전제로 파이프라인을 그렸는데, **그 파라미터는 실재하지 않는다.** 국중 seoji 가 판본에
> 따라 간헐적으로 목차를 주지만(10%) best-effort 수준이고, YouTube 가 도서 목차보다 나은
> 것을 4/4 로 준다는 사실을 발견해 설계를 뒤집었다.
> 하네스 [`scripts/l0_materials_probe.py`](../../blob/main/scripts/l0_materials_probe.py) · 실측 2026-09-01

## 0. 한 줄 요약

**도서 목차는 API 로 안정적으로 얻을 수 없다**(알라딘 0/10, 크롤링 불가, Google Books 0/3,
국중 seoji 1/10·판본별 편차). **대신 YouTube 재생목록이 커리큘럼과 분량을 4/4 로 준다** —
그것도 책 목차보다 나은 형태로, 단원마다 정확한 소요 시간이 붙어서. 도서에서 안정적으로
건진 것은 페이지 수(10/10)이고, 목차는 seoji 가 되면 덤(10% 확률)이다.

## 1. 왜 쟀는가

기존 자료 검색([`api/routes/materials.py`](../../blob/main/src/reaction_backend/api/routes/materials.py))은
Gemini 검색 그라운딩 1회가 전부인데, 상업 교재는 `finish_reason=RECITATION` 으로 막힌다
([`llm/provider.py:46`](../../blob/main/src/reaction_backend/llm/provider.py) 실측). 토익·공무원
수험서처럼 **목차가 가장 필요한 자료가 정확히 막히는 쪽**이라 기능이 사실상 죽어 있었다.

그래서 "LLM 이 읊게" 하지 말고 "우리가 API 로 가져오는" 쪽으로 뒤집으려 했다. 그 설계의
주춧돌이 알라딘 `OptResult=Toc` 였고, **ADR 을 쓰기 전에 그것부터 확인한 것이 이 스파이크다.**

## 2. 측정 결과

| 지표 | 알라딘 (도서 10건) | 국중 seoji (도서 10건) | YouTube (재생목록 4건) |
|---|---|---|---|
| M1 목차/커리큘럼 확보 | **0/10** | **1/10** (판본별) | **4/4** |
| M2 단원 파싱 | 0/10 | 1/10 (될 때 15챕터·516소단원) | 4/4 |
| M3 분량 확보 | **10/10** (페이지 수) | — | **4/4** (재생시간) |
| M4 지연 | 중앙 117ms · 최대 279ms | 중앙 ~180ms | 중앙 ~1.8s · 최대 3.2s |

주제 4종: 토익 · 자바 · 코딩테스트 · 정보처리기사. 상업 수험서(RECITATION 에 막히던 부류)와
기술서를 양쪽 다 덮게 골랐다.

### 2.1 알라딘 — `OptResult=Toc` 는 실재하지 않는다

`OptResult` 기구 자체는 정상 동작한다. 요청하면 `subInfo` 에 실제로 나타나는 값들:

    packing ✓   ebookList ✓   ratingInfo ✓   bestSellerRank ✓

그런데 목차는 **어떤 표기로도 반환되지 않는다**:

    Toc ✗   TOC ✗   toc ✗   tableOfContents ✗   contents ✗   Contents ✗   Story ✗

`subInfo` 는 언제나 `['subTitle', 'originalTitle', 'itemPage']` 뿐이다. 최상위 `description`
은 오지만 마케팅 문구 3문장이라 계획 분해에 쓸 수 없다:

> "토익 기초 단어부터 고난도 어휘까지 모든 난이도의 단어를 수록했다. …"

**얻은 것은 페이지 수와 ISBN 이다.** 10/10 으로 안정적이다 — 556p · 816p · 1022p · 1300p 등.

### 2.2 크롤링 폴백도 막혔다

| 소스 | 검색 페이지 | 상세 페이지 | 목차 |
|---|---|---|---|
| 알라딘 | 열림 (raw 307KB, ItemId 46건) | 열림 (raw 268~381KB) | **`"목차"` 0건 — `ajax.aspx` 후행 로드** |
| 교보 | 열림 (raw 578KB, ID 20건) | **raw 0 chars** | 불가 — 봇 차단 |
| Google Books | — | — | 한국 수험서 ISBN 3건 **전부 0건** |

추가로, 기존 [`web_fetch`](../../blob/main/src/reaction_backend/integrations/web_fetch/) 인프라를
커머스 페이지에 겨누면 **쓰레기가 나온다**: 알라딘 검색 페이지에서 내용이 처음 등장하는
위치가 4300자 지점인데 `_MATERIALS_MAX_CHARS = 2000` 에 잘려 순수 네비게이션 메뉴만 남는다.
[`extract.py`](../../blob/main/src/reaction_backend/integrations/web_fetch/extract.py) 는 #226 에서
강의계획서·요구사항 같은 단순 콘텐츠 페이지용으로 만들어졌고 주석도 "완벽한 본문 추출이
목적이 아니다" 라고 밝혀 두었다. 커머스 페이지는 다른 짐승이다.

목차를 크롤링으로 얻으려면 JS 실행(Playwright)이 필요한데, 새 무거운 의존성 + EC2 메모리라
AGENTS §8 대상이고 사이트 개편마다 깨진다. **접는다.**

**책 선택 탓이 아니라 구조 탓이다.** 처음 확인한 책이 단어장(VOCA)이라 "그 책은 원래 목차가
없었던 것 아니냐" 는 반론이 가능해, 목차가 확실히 있는 기술서로 다시 쟀다:

| 책 | raw | `"목차"` | `"Chapter"` |
|---|---|---|---|
| Java의 정석 : 기초편 | 282,799자 | **0건** | **0건** |
| 이것이 취업을 위한 코딩 테스트다 | 359,788자 | **0건** | **0건** |

알라딘은 책 종류와 무관하게 비-JS 요청에 목차를 내려주지 않는다. 확정.

### 2.3 YouTube — 책 목차보다 나은 것을 준다

이게 이 스파이크가 뒤집은 지점이다. 영상 제목이 곧 커리큘럼인데, 책 목차와 달리
**단원마다 정확한 분량이 붙어 온다**:

    책 목차   "Chapter 3 DFS & BFS"     ← 몇 시간짜리인지 모른다
    강의      "3. DFS & BFS [58분]"     ← 세션 배치가 산술이 된다

실측 (코딩테스트):

    1. [141분] (이코테 2021) 1. 코딩 테스트 출제 경향 분석 및 파이썬 문법 부수기
    2. [ 54분] (이코테 2021) 2. 그리디 & 구현
    3. [ 58분] (이코테 2021) 3. DFS & BFS
    … 외 12편 (총 15편 · 10.0시간)

실측 (토익) — 교재 단원과 강의 진도가 **이미 매핑돼 있다**:

    1. [27분] (ETS 토익 단기공략 750+) LC 1강 PART 1 UNIT 01-02
    2. [23분] (ETS 토익 단기공략 750+) LC 2강 PART 2 UNIT 03-04
    … 외 18편 (총 20편 · 10.0시간)

**뜻밖의 강점**: 코딩테스트·정보처리기사에서 **책과 같은 교재의 강의**가 검색으로 잡혔다.
이코테 604쪽 책 ↔ 이코테 15편 10시간 강의, 시나공 1300쪽 책 ↔ 시나공 200편 29시간 강의.
자료 한 세트를 책과 강의 양쪽으로 잡을 수 있다는 뜻이다.

| 주제 | 재생목록 | 편수 | 분량 |
|---|---|---|---|
| 토익 | ETS 토익 단기공략 750+ 최신개정판 LC+RC | 20 | 10.0시간 |
| 자바 | 2026 new 자바(Java) 프로그래밍 강의 | 107 | 13.2시간 |
| 코딩테스트 | (이코테 2021) 이것이 취업을 위한 코딩 테스트다 | 15 | 10.0시간 |
| 정보처리기사 | [2026] 시나공 정보처리기사 실기 기본서 | 200* | 29.0시간 |

\* 하네스의 200편 상한에 걸렸다. 실제 재생목록은 더 길 수 있다 — 상한을 **로그로 밝히지
않으면 "전부 셌다" 로 읽히므로** 여기 적어 둔다.

## 3. 판정

원래 기준은 "M1·M2 가 4/4 에 가까우면 알라딘 Toc API 로 간다. 절반 이하면 설계를 뒤집는다"
였다. **0/10 이므로 뒤집는다.** 다만 실패가 아니라 방향 전환이다:

1. **영상 강의를 1급 시민으로.** 커리큘럼과 분량이 둘 다 API 로 완전히 온다. 사용자 요청
   ("목차와 길이 양을 찾아서 계획")이 영상 경로에서 100% 충족된다.
2. **도서는 분량(페이지) 기반 보조.** 알라딘에서 페이지 수는 10/10 안정적으로 온다.
   "816쪽 ÷ 8주 = 주당 102쪽" 은 지금의 보편적 계획보다 훨씬 구체적이다.
3. **도서 목차는 seoji 로 best-effort 시도, 실패하면 사용자 붙여넣기(기존 HITL).**
   10% 확률로 완전한 목차가 덤으로 온다(§3.1). 안 오면 못 얻는 걸 얻는 척하지 않는다 —
   이건 `materials_for_prompt` 의 `(없음)` 규칙과 같은 판단이다.

### 3.1 국중 seoji — 판본에 따라 간헐적으로 목차를 준다 (10%)

**국립중앙도서관 seoji API** (`seoji.nl.go.kr`, 무료)에 키를 발급받아 10권 전체를 조회했다.
`BOOK_TB_CNT`(Table of ConTents) 필드가 실재하고, **채워지면 알라딘보다 훨씬 상세하다**:

    "Java의 정석 : 기초편"  →  15챕터 · 516소단원 · 정확한 페이지 번호 · 59,105자

앞부분 예시:

    Chapter 1. 자바를 시작하기 전에
      01 자바(Java)란? ·······································20
      02 자바의 역사 ·········································30
      03 자바의 특징 ·········································40
      …

**그런데 같은 책의 다른 판은 비어 있다.** 10권 전체 결과:

| ISBN | 제목 | `BOOK_TB_CNT` |
|---|---|---|
| …4765 / …2785 / …1832 | 해커스 토익 3종 | 0자 |
| …2032 | java의 정석 (구판) | 0자 |
| …9493 | Java의 정석 (3rd/2nd Edition 계열) | 0자 |
| **…9494** | **Java의 정석 : 기초편** | **59,105자 (15챕터)** |
| …3077 | 이것이 취업을 위한 코딩 테스트다 | 0자 |
| …1039 / …7507 / …0137 | 정보처리기사 수제비·시나공 3종 | 0자 |

**10권 중 1권(10%)만 채워져 있다.** 출판사가 납본할 때 선택적으로 채우는 필드로 보인다 —
같은 저자·같은 시리즈의 "기초편" 은 있고 "3rd Edition" 은 없는 걸 보면 판별 규칙성도 없다.

**표본을 줄이면 이 차이를 놓친다.** 처음엔 "주제당 대표 1권만 보면 된다" 고 가정하고
돌렸다가 하필 빈 판만 걸려 "seoji 에도 없다" 로 오판할 뻔했다 — 알라딘 `OptResult=Toc`
를 문서만 믿고 가정했다가 0/10 으로 틀린 것과 같은 실수 패턴이다. 하네스를 고쳐 **후보
전체**를 조회하게 만든 뒤에야 1/10 이 드러났다.

**판정: best-effort 보조로만 쓴다.** 10% 확률로 완전한 목차를 얹어주는 보너스 경로로
편입하고, 90% 는 §3 의 기본 설계(영상 강의 1급 시민 + 페이지 수 기반)로 간다.

기술적으로는 `probe_seoji` 가 **필드명을 추측하지 않는다** — 응답으로 온 모든 필드를
펼쳐 놓고 챕터 패턴이 가장 많이 잡히는 필드를 후보로 고른다. 못 찾으면 받은 필드 목록을
그대로 출력해 판정 근거를 남긴다.

## 4. 재현

```bash
export ALADIN_TTB_KEY=ttb...      # https://www.aladin.co.kr/ttb/wblog_manage.aspx
export YOUTUBE_API_KEY=AIza...    # GCP 콘솔 → YouTube Data API v3
export NL_SEOJI_KEY=...           # https://seoji.nl.go.kr/landingPage → 오픈API (선택)

uv run python -m scripts.l0_materials_probe            # 전체 4주제
uv run python -m scripts.l0_materials_probe --crawl    # 크롤링 판정 재현 (키 불필요)
```

키는 `.env` 에서도 읽는다(하네스가 새 의존성 없이 직접 파싱). 쿼터는 알라딘 5,000/일 ·
YouTube 10,000유닛/일이고, 전체 1회 실행이 알라딘 ~16회 · YouTube ~412유닛이라 여유가 크다.
