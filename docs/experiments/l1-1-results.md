## 6. 2차 지표 (참고용 — 성공 기준에 안 쓴다)

| 지표 | 값 |
|---|---|
| v1 vs v2 승률 | 0.803 (126승/31패/4무) |
| v2 vs v3 승률 | 1.000 (233승/0패/0무) |
| 축④(톤) 실격률 — v1 | **5.6%** (54/956 등장) |
| 축④(톤) 실격률 — v2 | 0.2% (2/954) |
| 축④(톤) 실격률 — v3 | 0.1% (1/950) |

H1-1 의 순서 가설(v3 > v2 > v1)과 방향이 일치한다: v1→v2 는 부분적 개선(패배·무승부가
실제로 존재), v2→v3 는 v1 상대로도 v2 상대로도 완승에 가깝다. v1 의 축④ 실격률(5.6%)이
v2/v3 보다 한 자릿수 높다는 것도 별도로 주목할 값 — 톤 축 하나만으로도 v1 이 상당수
비교에서 자동 패배(루브릭 §2 규칙 2)했을 가능성을 시사한다.

## 7. 한계·유보 (정직 표기 — 결과를 그대로 믿기 전에 볼 것)

이 표는 rubric-v1.md §5·preregistration-v1.md §7 이 미리 정해 둔 무효화 조건을
그대로 이 실측 값에 적용한 것이다. 사후에 새로 지어낸 기준이 아니다.

| 항목 | 상태 | 의미 |
|---|---|---|
| **Swap consistency < 0.70** (수치 폐기 조건) | 미해당(0.987) | 승률 수치를 그대로 써도 된다 |
| **Judge–human κ**(L1-2) | **미실시** | **self-enhancement bias(생성·심판이 같은
  provider) 를 아직 배제하지 못했다.** 이 문서의 승률이 "인간이 봐도 v3 가 이겼다"를
  아직 보증하지 않는다 — L1-2 가 나와야 이 결과를 본문 결론으로 쓸지, 부록으로 내릴지
  최종 결정된다(계획서 L1-2 성공 기준) |
| **235전 235승 0패 0무** | 이례적으로 깨끗함 | 표에서 보듯 v1-v2(80.3%)는 실제 편차가
  있어 심판이 기계적으로 "더 채워진 JSON"에 표를 주는 것만은 아니라는 정황은 있다.
  그래도 이 정도의 완승은 시각적으로 재확인할 가치가 있다 — 다음 단계(L1-2)에서 사람
  라벨과 대조할 때 우선적으로 볼 것 |
| **골든셋은 전량 합성(synthetic)** | 실 로그 0건 | `eval/README.md` 가 이미 명시한
  한계 — 실사용 데이터가 아니라 설계자가 쓴 시나리오에 대한 결과다 |
| **원본 판정/생성 데이터 미보존** | `eval/l1_1_*.jsonl` 은 커밋 안 됨 | 이 문서의 표가
  유일한 영속 기록이다. 축별(①~⑤) 점수 분포, 개별 카드 텍스트 재검토가 필요해지면
  **재실행**해야 한다(같은 시드라 A/B 배정은 재현되지만, LLM 생성·판정 자체는 비결정적
  이라 바이트 단위 재현은 안 된다) |

## 8. 다음 단계

1. **L1-2(judge–human κ)** — 이 결과의 신뢰도를 결정하는 다음 관문. 인간 2인이 라벨링한
   표본과 이 심판 판정을 대조해야 self-enhancement bias 를 실제로 배제할 수 있다.
2. **v3 프로덕션 승격 여부는 아직 결정하지 않는다** — `_PROMPT_ID` 는 여전히 `@v2` 로
   고정돼 있다(#272, #275). 이 문서의 결과가 긍정적이라고 해서 자동으로 승격되지
   않는다 — L1-2 확인 후 별도 판단.
3. 필요하면 L1-1 결과를 표본을 늘려 재실행할 수 있다 — 하네스(`l1_1_generate.py`/
   `l1_1_judge.py`/`l1_1_analyze.py`)는 이미 완성돼 있다(#273, #274, #275).

## 9. 재현 방법

```bash
# 1) 생성 (실 API 호출, 비용 발생 — 21건/1,080건 정도 fallback 예상)
uv run python -m scripts.l1_1_generate

# 2) 판정 (실 API 호출, 최대 1,440건)
uv run python -m scripts.l1_1_judge

# 3) 분석 (LLM 호출 없음, 순수 계산)
uv run python -m scripts.l1_1_analyze
```

`RANDOM_SEED`/`BOOTSTRAP_SEED` 가 고정돼 있어 A/B 배정과 부트스트랩 리샘플링은
재현되지만, LLM 생성·판정 자체가 비결정적이라 승률 수치는 재실행마다 소폭 달라질 수
있다.
